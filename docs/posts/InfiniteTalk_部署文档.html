InfiniteTalk 部署文档（初学者友好版）

适用于：RTX 4090D 24GB / 国内服务器 / Ubuntu 22.04

0. 先看这里：这篇文章能帮你做什么

这是一篇 手把手教程，不是参考手册。从头到尾按顺序做，每一步都有：

  • 你要做什么（人话）
  • 复制粘贴什么命令
  • 正常情况下应该看到什么
  • 如果出问题怎么办

学完你能做什么：把一张人物图片 + 一段唱歌音频，变成一个该人物跟着唱歌的视频。

学完你不能做什么：换声音。InfiniteTalk 只负责让画面跟着音频动，它不会唱歌也不会变声。要变声请先用 RVC / So-VITS / GPT-SoVITS 等工具处理音频。

1. 你的机器是什么情况

项目 配置
GPU 1 块 RTX 4090D，24GB 显存
CPU 16 核
内存 62GB
系统盘 30GB（只放系统、miniconda、虚拟环境，不放模型）
数据盘 210GB（模型、输出视频都放这里）
数据盘路径 /root/autodl-tmp
Python 初始环境有 Python 3.12（不要用，要重建 Python 3.10）
CUDA 12.4
PyTorch 初始环境有 2.5.1+cu124

2. 开始前你要准备好的东西

  • 一张人物图片（png 或 jpg，单人正脸，嘴不要被遮住）
  • 一段唱歌音频（mp3 或 wav，建议 10-20 秒，人声尽量清楚）
  • 一个终端连上这台服务器

3. 部署（跟着做，环境安装约 30-60 分钟，模型下载约 1-3 小时）

第一步：进入数据盘

为什么：系统盘只有 30GB，放不下模型。数据盘 210GB，所有东西放这里。

cd /root/autodl-tmp
mkdir -p infinitetalk-work
cd infinitetalk-work

确认你进去了：

pwd

你应该看到：

/root/autodl-tmp/infinitetalk-work

第二步：建 Python 3.10 环境

为什么：项目依赖在 Python 3.12 下容易报错，3.10 最稳。

conda create -n infinitetalk python=3.10 -y

看到 done 后执行：

conda activate infinitetalk

验证环境版本：

python --version

应该看到：

Python 3.10.x

如果看到 Python 3.12.x，说明环境没切换成功。重新执行 conda activate infinitetalk。

第三步：配国内源

为什么：服务器在国内，直连国外 pip 源会很慢甚至下不动。

pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
pip config set global.trusted-host pypi.tuna.tsinghua.edu.cn

不用等输出，执行完就行。

第四步：装 PyTorch

为什么：虽然有初始环境的 PyTorch，但那是装在 Python 3.12 里的，你现在用的是 Python 3.10，需要重新装一份。

注意：这条命令必须走官方 PyTorch 源，不能用国内镜像。下载会比较慢（5-20 分钟），正常。

pip install torch==2.5.1 torchvision==0.20.1 torchaudio==2.5.1 \
  --index-url https://download.pytorch.org/whl/cu124 \
  --timeout 120 \
  --retries 10

装完后验证：

python -c "import torch; print(torch.__version__); print(torch.version.cuda); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"

应该看到类似：

2.5.1+cu124
12.4
True
NVIDIA GeForce RTX 4090D

如果 True 没出现，说明 GPU 不可用，不要继续。

第五步：装 xformers

pip install xformers==0.0.28.post3 --index-url https://download.pytorch.org/whl/cu124

验证：

python -c "import xformers; print(xformers.__version__)"

应该看到：

0.0.28.post3

第六步：装 flash_attn

pip install ninja psutil packaging wheel setuptools
pip install misaki[en]
pip install flash_attn==2.7.4.post1 --no-build-isolation

验证：

python -c "import flash_attn; print('flash_attn ok')"

应该看到：

flash_attn ok

如果这一步报错，把完整报错贴给 ChatGPT/Claude。最常见的原因是机器没有 nvcc（CUDA 编译器）。

第七步：下载项目代码

为什么：GitHub 直连国内容易断，用代理地址。

先回到数据盘：

cd /root/autodl-tmp/infinitetalk-work

下载代码：

git clone --depth 1 https://gh.llkk.cc/https://github.com/MeiGen-AI/InfiniteTalk.git

看到 done 后进入：

cd InfiniteTalk
pwd

应该看到：

/root/autodl-tmp/infinitetalk-work/InfiniteTalk

第八步：安装项目依赖

pip install -r requirements.txt

会装很多包，等它跑完。然后装 ffmpeg 和 librosa：

conda install -c conda-forge ffmpeg librosa -y

验证：

ffmpeg -version

应该看到 ffmpeg 版本信息（一堆文字），不是 command not found。

python -c "import librosa; print('ok')"

应该看到：

ok

第九步：配置 Hugging Face 国内镜像

为什么：模型存在 Hugging Face 上，直连慢，用国内镜像加速。

export HF_ENDPOINT=https://hf-mirror.com
pip install -U "huggingface_hub[cli]"

重要：每次新开终端下载模型前，都要先执行 export HF_ENDPOINT=https://hf-mirror.com。

第十步：下载模型（约 100GB，等 1-3 小时）

先在项目目录里创建权重文件夹：

cd /root/autodl-tmp/infinitetalk-work/InfiniteTalk
mkdir -p weights

10.1 下载 Wan2.1 基座模型（约 66GB）

这是什么：14B 参数的视频生成基础模型，是 InfiniteTalk 的”底座”。

hf download Wan-AI/Wan2.1-I2V-14B-480P \
  --local-dir weights/Wan2.1-I2V-14B-480P \
  --include "diffusion_pytorch_model-*.safetensors" \
  --include "diffusion_pytorch_model.safetensors.index.json" \
  --include "config.json" \
  --include "Wan2.1_VAE.pth" \
  --include "models_t5_umt5-xxl-enc-bf16.pth" \
  --include "models_clip_open-clip-xlm-roberta-large-vit-huge-14.pth" \
  --include "google/umt5-xxl/*" \
  --include "xlm-roberta-large/*"

下载时间较长。如果中途断了，不要删文件，重新执行同一条命令即可续传。

10.2 下载 wav2vec 音频编码器（约 2GB）

这是什么：把音频转成模型能理解的数字特征。

hf download TencentGameMate/chinese-wav2vec2-base \
  --local-dir weights/chinese-wav2vec2-base

hf download TencentGameMate/chinese-wav2vec2-base model.safetensors \
  --revision refs/pr/1 \
  --local-dir weights/chinese-wav2vec2-base

10.3 下载 InfiniteTalk 单人权重（约 9GB）

这是什么：让 Wan2.1 能”听懂”音频的附加权重。

hf download MeiGen-AI/InfiniteTalk \
  --local-dir weights/InfiniteTalk \
  --include "single/infinitetalk.safetensors"

10.4 下载 fp8 量化权重（约 24GB，建议下载）

这是什么：24GB 显存卡跑不动完整模型，fp8 量化版更省显存。备用。

hf download MeiGen-AI/InfiniteTalk \
  --local-dir weights/InfiniteTalk \
  --include "quant_models/infinitetalk_single_fp8.safetensors" \
  --include "quant_models/infinitetalk_single_fp8.json" \
  --include "quant_models/quant.json" \
  --include "quant_models/t5_fp8.safetensors" \
  --include "quant_models/t5_map_fp8.json"

第十一步：检查模型都下好了没有

ls weights/Wan2.1-I2V-14B-480P

应该看到很多文件名，至少包含 config.json、Wan2.1_VAE.pth、diffusion_pytorch_model-*.safetensors。

ls weights/InfiniteTalk/single

应该看到：

infinitetalk.safetensors
ls weights/InfiniteTalk/quant_models

应该看到：

infinitetalk_single_fp8.safetensors
t5_fp8.safetensors

如果少了哪个，回到第十步重新执行对应的下载命令。hf 不会重复下载已有文件。

第十二步：修一个代码 Bug（必须做，否则会报错）

问题：新版本 transformers 默认用 sdpa 注意力机制，但 InfiniteTalk 的 wav2vec2 代码要求 output_attentions=True，两者冲突。

修复：编辑一个文件，加一行代码。

nano src/audio_analysis/wav2vec2.py

用方向键往下翻，找到这一行（大概在前 30 行）：

self.config.output_attentions = True

在它上面一行插入：

self.config._attn_implementation = "eager"

改完后这两行应该是：

self.config._attn_implementation = "eager"
self.config.output_attentions = True

保存步骤：

  1. 按 Ctrl + O（字母 O，不是数字 0）
  2. 按 Enter 确认文件名
  3. 按 Ctrl + X 退出

第十三步：测试环境是否正常

用官方示例跑一次，确认环境没问题。24GB 卡不建议一开始用 40 steps，先用 10 steps 快速确认环境能跑：

python generate_infinitetalk.py \
  --ckpt_dir weights/Wan2.1-I2V-14B-480P \
  --wav2vec_dir weights/chinese-wav2vec2-base \
  --infinitetalk_dir weights/InfiniteTalk/single/infinitetalk.safetensors \
  --input_json examples/single_example_image.json \
  --size infinitetalk-480 \
  --sample_steps 10 \
  --mode streaming \
  --quant fp8 \
  --quant_dir weights/InfiniteTalk/quant_models/infinitetalk_single_fp8.safetensors \
  --motion_frame 9 \
  --num_persistent_param_in_dit 0 \
  --sample_audio_guide_scale 4.5 \
  --save_file test_official

预期：

  • 加载权重时有一堆 Loading 进度条
  • 看到 Generating video ...
  • 进度条慢慢走（2% 停很久正常，别急）
  • 最后没有红色报错，输出 test_official 开头的 mp4 文件

进度慢是正常的：4090D 24GB 跑 fp8 模式，首次加载模型最慢。10 steps 是快速验证方案；如果改成 40 steps，10 秒视频可能需要 4-5 小时。

4. 用自己的图片和音频生成视频

部署成功后，下面是每次使用的流程。

4.1 准备工作

每次新开终端都要先激活环境：

conda activate infinitetalk
cd /root/autodl-tmp/infinitetalk-work/InfiniteTalk

4.2 上传图片和音频

把你的文件放到 inputs/ 文件夹里：

mkdir -p inputs

上传后执行 ls inputs，你应该看到你的图片和音频文件。

假设你的文件是：

inputs/my_photo.png      # 人物图片
inputs/my_song.mp3       # 唱歌音频

图片支持 png / jpg / jpeg。如果文件名不一样，后面步骤里把路径改成你的实际文件名。

4.3 把 MP3 转成 WAV

为什么：WAV 格式最稳，避免各种音频读取兼容问题。

ffmpeg -i inputs/my_song.mp3 -ar 16000 -ac 1 inputs/my_song_16k.wav

把 my_song.mp3 换成你的真实文件名。

你应该看到：一堆输出，最后有 size= 和 time= 信息，没有 error。

4.4 创建输入配置文件

nano inputs/my_config.json

把下面内容复制进去：

{
  "prompt": "A person is singing naturally, with accurate lip sync, expressive facial movements, and stable identity.",
  "cond_video": "inputs/my_photo.png",
  "cond_audio": {
    "person1": "inputs/my_song_16k.wav"
  }
}

注意：

  • cond_video 填你的图片路径（字段名叫 video 但填图片没问题）
  • person1 填你转好的 wav 路径
  • 如果你的图片叫 abc.jpg，就写 "cond_video": "inputs/abc.jpg"

保存：

  1. Ctrl + O → Enter
  2. Ctrl + X

4.5 生成视频

24GB 显存卡有两个选择：

选择 A：快速出片（推荐，约 1-1.5 小时完成 10 秒视频）

python generate_infinitetalk.py \
  --ckpt_dir weights/Wan2.1-I2V-14B-480P \
  --wav2vec_dir weights/chinese-wav2vec2-base \
  --infinitetalk_dir weights/InfiniteTalk/single/infinitetalk.safetensors \
  --input_json inputs/my_config.json \
  --size infinitetalk-480 \
  --sample_steps 10 \
  --mode streaming \
  --quant fp8 \
  --quant_dir weights/InfiniteTalk/quant_models/infinitetalk_single_fp8.safetensors \
  --motion_frame 9 \
  --num_persistent_param_in_dit 0 \
  --sample_audio_guide_scale 4.5 \
  --save_file my_video

选择 B：高质量（慢，约 4-5 小时完成 10 秒视频）

把上面的 --sample_steps 10 改成 --sample_steps 40，--sample_audio_guide_scale 4.5 改成 4.0。

时间估算是基于 RTX 4090D 24GB + fp8 + num_persistent_param_in_dit 0 实测。更大显存的卡会快很多。详见第 7 节。

4.6 找到生成的视频

ls *.mp4

或者：

find . -name "my_video*"

看到 .mp4 文件就是结果。用 AutoDL 文件管理下载到本地。

5. 效果不满意怎么调

问题 怎么改
嘴型跟不上歌词 把 --sample_audio_guide_scale 从 4 改成 5
脸变形、动作太奇怪 把 --sample_audio_guide_scale 从 4 改成 3
生成太慢 把 --sample_steps 从 40 改成 10（10 已实测可接受），详见第 7 节速度和成本控制
报错 CUDA out of memory 确认有 --num_persistent_param_in_dit 0 和 --quant fp8 两行
颜色漂移 降低 --color_correction_strength（范围 0.0-1.0）

6. 所有参数详解（从源代码逐项核对）

每个参数来源于 generate_infinitetalk.py 的 argparse 定义和实际调用逻辑。

参数 默认值 作用
--ckpt_dir 无 Wan2.1-I2V-14B 基座模型权重目录。指向 weights/Wan2.1-I2V-14B-480P。
--wav2vec_dir 无 wav2vec2 音频编码器权重目录。指向 weights/chinese-wav2vec2-base。
--infinitetalk_dir 无 InfiniteTalk 单人权重文件路径（单个 safetensors）。指向 weights/InfiniteTalk/single/infinitetalk.safetensors。
--input_json examples.json JSON 配置文件路径。里面写 cond_video（图片路径）、cond_audio.person1（音频路径）、prompt。
--size infinitetalk-480 输出分辨率档位。可选 infinitetalk-480 或 infinitetalk-720。24GB 显存只能用 480。输出宽高比自动跟随输入图片。
--sample_steps 40（I2V 默认） 扩散模型采样步数。步数越高画质越好但越慢。40 质量好但时间久，20 中等，10 可快速出片且效果可接受。不建议低于 5。
--sample_shift 7（480P）/ 11（720P） Flow matching 调度器的时间偏移因子。默认按分辨率自动设，一般不用改。值越大画面变化幅度越大。
--sample_text_guide_scale 5.0 文本引导强度（CFG）。控制画面按 prompt 文字描述执行的程度。不用 LoRA 时建议 3-7，用了 LoRA 时降为 1。
--sample_audio_guide_scale 4.0 音频引导强度（CFG）。控制嘴型跟随音频的力度。这是控制嘴型同步的最重要参数。值越高嘴型越准但画面可能变形/抖动，值越低画面稳但嘴跟不上。唱歌建议从 4 开始试，不准就调到 5。不用 LoRA 时 3-5，用 LoRA 时降为 2。
--mode clip 生成模式。clip：只生成一段视频块（--frame_num 帧）。streaming：流式逐段生成长视频（最长到 --max_frame_num 帧）。唱歌长视频必须用 streaming。
--frame_num 81 每段视频块生成多少帧，只在 clip 模式下生效。必须是 4n+1（如 81 = 4×20+1）。
--max_frame_num 1000 streaming 模式下最大总帧数。默认 1000 帧约 40 秒（25fps 计算）。10 秒音频不会触顶。
--motion_frame 9 streaming 模式每段的驱动帧长度。影响长视频生成时相邻段之间的动作连续感。取默认值 9 即可。
--quant 无（不量化） 量化类型。可选 fp8 或 int8。把模型转低精度以大幅降低显存。24GB 卡强烈建议设 fp8。量化后显存省，速度也会快一些，但画质轻微下降。
--quant_dir 无 量化版权重目录。指向包含 infinitetalk_single_fp8.safetensors、t5_fp8.safetensors 等文件的目录。必须配合 --quant fp8 使用。
--num_persistent_param_in_dit 无（不限制） DiT 模型常驻显存的参数量上限。设为 0 表示不常驻，所有参数边用边加载/卸载。这是 24GB 卡能跑的关键参数，设为 0 显存最省但速度会慢。设大值或不设会更快但可能 OOM。
--use_teacache False 开启 TeaCache 加速。跳过部分采样步中重复计算来提速，可能轻微影响嘴型精度。
--teacache_thresh 0.2 TeaCache 阈值。值越小跳过越多（更快但可能更粗糙），越大越接近完整推理。建议 0.1-0.3 之间试。
--use_apg False 开启自适应投影引导。可改善画质和稳定性，但额外消耗显存。24GB 卡慎开。
--offload_model 单卡默认 True 每次前向计算后是否把模型卸载到 CPU。省显存但慢。单卡模式自动开启。
--base_seed 42 随机种子。同一图片、同一音频、同一种子可以复现完全一样的结果。传 -1 则每次随机。
--lora_dir 无 LoRA 权重文件路径。配合 FusionX / Lightx2v 等加速 LoRA 使用，步数可降到 4-8。
--lora_scale 1.2 LoRA 影响强度。配合 --lora_dir 使用。值越大 LoRA 效果越强。
--color_correction_strength 1.0 颜色校正强度，范围 0.0-1.0。降低可以缓解 I2V 长视频的颜色漂移问题。
--save_file 自动生成 输出视频文件名前缀（不含扩展名）。最终生成 前缀.mp4。不设则自动用时间戳命名。

7. 速度和成本控制（实战经验）

7.1 时间参考（24GB 卡实测）

以下数据在 RTX 4090D 24GB + fp8 + num_persistent_param_in_dit 0 上实测：

配置 每步耗时 10 秒音频总耗时 质量
streaming + 40 steps 约 113 秒 4-5 小时 较好
streaming + 20 steps 约 113 秒 2-2.5 小时 中等
streaming + 10 steps 约 113 秒 1-1.5 小时 可接受，推荐
streaming + 5 steps 约 113 秒 30-45 分钟 明显下降
clip + 10 steps + frame_num 81 约 113 秒 每段约 15-25 分钟 单段可接受

7.2 为什么 40 steps 这么慢

瓶颈不是算力，是 24GB 显存不够：

24GB 显存
  ↓
必须开启 fp8 + num_persistent_param_in_dit 0
  ↓
模型参数频繁在显存和 CPU 之间换入换出
  ↓
每步很慢（约 113 秒）
  ↓
streaming 模式还要分段
  ↓
总耗时 × 段数

7.3 推荐省钱路线

正规做法（不推荐 24GB 卡上跑）：

第一次测试视频：2 秒音频 + sample_steps 10 + clip
验证环境没问题

真实使用推荐路线：

第一步：用轻量 lip-sync 工具先试效果
        如 MuseTalk、LatentSync、Wav2Lip
        成本低、速度快
        确认图片/音频值得做

第二步：确认素材值得，再用 InfiniteTalk 精修
        建议租 48GB+ 显存卡
        如 L40S、A800、RTX PRO 6000
        不用极限省显存，速度明显提升

如果坚持在 24GB 卡上跑 InfiniteTalk：

优先：streaming + sample_steps 10
更快：streaming + sample_steps 10 + use_teacache
最快：split 音频分段 + clip + sample_steps 10（但需手动拼接）

7.4 快速出片案例命令

适合：24GB 卡、想一次性生成完整 10 秒视频、质量可接受。

python generate_infinitetalk.py \
  --ckpt_dir weights/Wan2.1-I2V-14B-480P \
  --wav2vec_dir weights/chinese-wav2vec2-base \
  --infinitetalk_dir weights/InfiniteTalk/single/infinitetalk.safetensors \
  --input_json inputs/my_singing.json \
  --size infinitetalk-480 \
  --sample_steps 10 \
  --mode streaming \
  --quant fp8 \
  --quant_dir weights/InfiniteTalk/quant_models/infinitetalk_single_fp8.safetensors \

7.5 想更快可以试的选项

方法 命令改动 速度提升 质量影响
降步数 --sample_steps 8 比 10 快约 20% 细节略降
开 TeaCache 加 --use_teacache --teacache_thresh 0.2 可能再快 20-40% 嘴型可能更松
分 3 段 clip 生成再拼接 用 ffmpeg 切音频，分 3 次 clip，最后 ffmpeg 拼 每段 15-25 分钟，可重叠跑 段间可能有跳变
租更大显存卡 48GB+ 如 L40S / A800 不用极限 offload，可能数倍提升 质量可更好（不强行量化）

7.6 不影响质量的加速

以下选项可以提速但几乎不影响质量：

  • 只降 sample_steps 到 10（你已验证可接受）
  • 租 48GB+ 显存卡

以下选项会同时影响质量和速度：

  • use_teacache
  • 降 sample_steps 到 5
  • 分 clip 手动拼接

8. 素材建议

图片：

  • 单人，正脸或微微偏头
  • 嘴不要被手、口罩、墨镜挡住
  • 脸清楚，不要模糊
  • 上半身比纯大头照更自然

音频：

  • wav 格式，16kHz 单声道
  • 人声清楚，伴奏不要太大声
  • 不要太多混响/回声
  • 每段 10-30 秒效果最好
  • 超过 60 秒的画面容易变色，建议切成多段分别生成再拼接

11. AutoDL 保存策略：只保存镜像，不保存数据盘

这次部署的一个重要经验：如果只是偶尔用，不建议长期保存数据盘。

11.1 为什么不建议保存数据盘

模型权重很大：

内容 大小
Wan2.1-I2V-14B-480P 精简权重 约 66-80GB
InfiniteTalk single 约 9GB
InfiniteTalk fp8 量化权重 约 24GB
wav2vec 约 1-2GB
输出视频、缓存 若干 GB

如果 AutoDL 保存数据盘按天收费，长期保存这些模型可能比下次重新下载更贵。

11.2 保存镜像大概率会保存什么

你的 conda 在：

/root/miniconda3

conda create -n infinitetalk python=3.10 创建的环境通常在：

/root/miniconda3/envs/infinitetalk

这属于系统盘 /root。如果 AutoDL 的“保存镜像”保存的是系统盘，那么这些大概率会保留：

  • miniconda
  • infinitetalk 虚拟环境
  • PyTorch / torchvision / torchaudio
  • xformers
  • flash_attn
  • pip 安装的 Python 依赖

11.3 不保存数据盘会丢什么

这些在数据盘 /root/autodl-tmp，不保存数据盘就会丢：

/root/autodl-tmp/infinitetalk-work/InfiniteTalk
/root/autodl-tmp/infinitetalk-work/InfiniteTalk/weights
/root/autodl-tmp/infinitetalk-work/InfiniteTalk/inputs
/root/autodl-tmp/infinitetalk-work/InfiniteTalk/*.mp4

也就是说：

  • 项目代码会丢
  • 模型权重会丢
  • 输入图片/音频会丢
  • 输出视频会丢
  • 手动修过的 src/audio_analysis/wav2vec2.py 会丢

11.4 下次重开机器的最省钱流程

如果你只保存镜像、不保存数据盘，下次使用时：

1. 选择保存好的镜像开机
2. 扩容数据盘到 200GB+
3. 进入 /root/autodl-tmp/infinitetalk-work
4. 重新 git clone 项目
5. 重新下载 weights
6. 重新修 wav2vec2.py 的 eager attention 那一行
7. 上传图片和音频
8. 执行快速生成命令

环境大概率不用重装，模型和代码需要重新准备。

11.5 如何确认虚拟环境是否会保留

在服务器里执行：

conda info --envs

如果看到：

infinitetalk    /root/miniconda3/envs/infinitetalk

说明环境在系统盘。保存镜像后大概率还在。

12. 项目能做什么、不能做什么

能做什么：

  • 一张图片 + 一段音频 → 图片里的人物跟着音频唱歌/说话的视频
  • 一段视频 + 一段音频 → 给视频换配音，保留原镜头和动作
  • 多人场景（需要下载多人权重）

不能做什么：

  • 不能变声：你想让男声变女声、普通声音变歌手声音，InfiniteTalk 做不到。先用 RVC、So-VITS、GPT-SoVITS 等工具把音频变声，再把变声后的音频交给 InfiniteTalk。
  • 不能自己唱歌：InfiniteTalk 不会生成音频，你必须自己提供音频文件。
  • 不能从文字生成唱歌：它不能像 Suno 那样输入歌词就生成歌曲。

如果你想换声音，完整流程是：

原始歌曲 mp3
    ↓
RVC / So-VITS / GPT-SoVITS 变声
    ↓
新的声音 mp3
    ↓
ffmpeg 转 wav
    ↓
InfiniteTalk 生成视频
    ↓
变声后的唱歌视频

InfiniteTalk 负责的是最后一步：让画面里的人跟着你提供的音频动起来。
