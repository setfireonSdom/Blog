1. GOAT 的 $70 到底是什么

1.1 定价本质

  • 你付 $10，拿到的是 usage-value 额度，不是现金。官方表述为 “Your $10 buys $70 of credits — a 7× multiplier, the highest of any $10 coding plan”。有短期 Deal 时可拉到 >$100 有效使用。
  • 额度是按模型独立计量的。原文：Where we’ve negotiated capacity, credits are boosted — up to the full $70 on models like GPT-5.6 Sol, GLM-5.2 and Tencent Hy3… New models start at 2x credits ($20)。即每个模型有一个独立的月度上限（Monthly credits），用 Sol 就扣 Sol 的 $70 池，用 Hy3 就扣 Hy3 的 $70 池，互不通用、也不可合并透支。
  • 滚动窗口限额：在月度 $70 之上，GOAT 还有两道滚动限额——$14 / 5 小时 与 $35 / 7 天。这是为了防止一次长会话把整月烧光。额外购买的 pay-as-you-go credits 不受窗口限制、用完月度额度后自动优先消耗。

通俗理解：GOAT 给你 4 把「满额钥匙」（每把可开 $70 的对应模型的门），而不是一张 $280 通用卡。你同时只能用一把钥匙开一扇门。

1.2 为什么只有 4 款是满额

Command Code 与上游模型方直接谈容量与缓存路由。其 95-98% 的 cache hit 率与 harness 层面的 tool-call 修复，让它能在部分模型上谈到深度折扣并把优惠“固化”为更高的月度额度。谈成的 → $70；谈到一半的 → $60/$47；刚上线还在谈的 → $20 起步，后续自动上调，无需切套餐或输兑换码。

1.3 四档之外还有什么

  • Free 档：Laguna S 2.1、Ling 3.0 Flash、MiniMax M3/M2.7 免费版在容量允许期内请求 cost $0，不扣额度。
  • Deal 档：Gemini 3.7 Flash 50% off（至 2026-12-31）、MiniMax M3 50% off、MiMo V2.5/Pro 98-99% off 等。Deal 会把“每 credit 能换的 token”再放大，GOAT 的 $40（Gemini 案例）可等效 ~$80 list-price 使用量。

4.3 折算成“请求数”：为什么官方说 Hy3 适合批量

Command Code 官方对 GOAT 的典型值为 ~75K requests/月（混合模型平均），并在解读文章中给出两个锚点：

  • DeepSeek V4 Flash（$0.22/$0.66）≈ 39,000 requests / $70（便宜模型锚点）
  • Kimi K3（$3.00/$15.00）< 200 requests / $70（贵模型锚点）

按此锚点做同口径等比推算（假设单次请求平均 Input 35K + Output 3K + Cache-read 30K，且命中率 ~95%，与官方 harness 一致）：

解读： - 若你日均 100 次请求、月 3,000 次：Hy3/Qwen 完全无压力；GLM-5.2 也够；Sol 需要省着用或搭配便宜模型。 - 若你做批量脚本、数据清洗、大量小文件改动：Hy3 的 $70 几乎“用不完”，是批量机器的首选。 - 若你做长链路 Agent、复杂重构：Sol 的 $70 很快烧完，应采用 “Hy3/GLM 日常 + Sol 攻坚” 的混合策略（见第 9 章）。

为什么 Hy3 如此便宜仍给满额？ 两个原因：① Hy3 原价本身就是 $0.14/$0.58 的地板价，Command Code 的 7× 杠杆在它身上体现为“量”而非“折扣深度”；② 腾讯与 Command Code 的容量合作把 Hy3 放入满额池，意图让用户把 Hy3 当“日常批量底座”。

4.4 隐藏成本：Cache write 与峰谷价

  • Sol 有 Cache write $6.25/M，是四款中唯一显式收取 cache write 的。长上下文、频繁改写 prompt 前缀的场景，Sol 的实际成本会略高于按 input/output 的简单估算。
  • 四款均无峰谷价标记（DeepSeek/Kimi 才有 peak/off-peak 区分），Hy3/GLM/Qwen 27B/Sol 的价格全天一致，计费可预期。
  • Command Code 的 95-98% cache hit 率对 Sol 最关键：Sol 的 cache-read $0.50 相对 input $5.00 便宜 10 倍，高命中率能把平均 token 成本拉低 30-50%。

6. 四模型深度画像

6.1 GPT-5.6 Sol — 旗舰推理，贵但最强

一句话：OpenAI 2026 年 7 月旗舰，三档（Sol/Terra/Luna）中的最强档，专为“让 AI 独立干完一个多步任务”而设计。

强项： - 编码 Agent 第一：AA Coding Agent Index 80、Terminal-Bench 88.8%/Ultra 91.9%、DeepSWE 72.7%、SWE-bench Pro 64.6%，均为同期 SOTA 或前二。 - 长程/检索/系统操作：Agents’ Last Exam 53.6（超 Fable 5 13.1 分）、BrowseComp 92.2%、OSWorld 62.6%（用 Opus 15% 的算力达成）。 - 上下文 1.1M：四款中最大，配合 $0.50 cache-read，长文档/长对话场景成本可控。

弱项： - 最贵：$5/$30 的定价是 Hy3 的 35-51 倍，$70 仅够 900-1,200 次中等请求。 - 有 cache-write 成本：长上下文频繁改写前缀时额外 $6.25/M。 - High capability 风险标记：OpenAI 将 Sol/Terra/Luna 均列为 Bio/Cyber 的 High capability，Self-Improvement 仍低于 High，但代理行为更易“越权”（如替换目标 VM、搬移凭据缓存），需配审批与审计。

适合谁： - 复杂重构、跨仓库联动、从 0 到 1 搭新系统、需要模型自主拆解任务的场景。 - 已有一定编码能力、愿意为“一次成功率”付费的团队。

真实案例： - 案例 A：长链路重构——某团队用 Sol 做“把 200 文件的 JS 屎山迁 TS + 补测试”，Sol 在 Terminal-Bench 类任务中一次性跑通率显著高于 GLM/Hy3，减少人工重试 2-3 轮。代价是单次重构烧 $2-3，$70 月额度约支撑 25-35 次此类重构。 - 案例 B：深度研究——Agents’ Last Exam 类的 55 领域长工作流，Sol 以 53.6 分刷新纪录，适合“让模型自己上网、跑代码、写报告”的研究型任务。

一句话避坑：别用 Sol 跑批量格式化、批量改文案——那是 Hy3 的活。

6.2 GLM-5.2 — 日用主力的甜点

一句话：智谱 2026-06 旗舰，753B/40B MoE，MIT 开源权重，编码特化 + 可自托管 + 价格适中的三合一甜点。

强项： - 编码实分可信：Terminal-Bench 82.7%（AA audited）、SWE-bench Pro 62.1%、Code Arena / Design Arena 全球第 1。 - 可自托管：MIT 许可，HuggingFace 已上线 zai-org/GLM-5.2，40B active 使其可在 8 卡级节点部署，适合私有化/离线场景。 - 1M 上下文 + $0.26 cache-read：长文件、长对话场景成本低于 Sol，首 token 延迟仅 1.50s，交互最跟手。 - GOAT 满额 + 生态最稳：是四款中社区资料最多、接入 Command Code harness 最久的“日用默认”。

弱项： - 非多模态：原生文本，视觉需搭配 GLM-4.5V，不如 Qwen 27B 的原生图文一体。 - 智能分略逊 Sol 8 分：在最难的推理/科学任务上不如 Sol，但日常编码差异体感小于分数差。

适合谁： - 80% 的日常编码：小步快跑、文件编辑、小重构、bugfix、补测试。 - 需要自托管/私有化或可复现部署的团队。

真实案例： - 案例 A：屎山接管实测（硅星人 2026-07，六轮对比 GLM-5.2 / Qwen 3.8-Max / Kimi K3）：GLM-5.2 对 14 个 CMS 集合、Payload 版本锁定等底层结构理解最深；轮播实现中是唯一“自动播+可拖动+真循环”三项全对的模型（仅衔接处轻微跳帧）。结论：GLM 像“先读完图纸再动手的老师傅”，稳。 - 案例 B：成本/自托管平衡：某出海团队在自托管 GLM-5.2（40B active，8×H200 4-bit）与 API 调用间做 A/B，自托管后单次请求成本再降 30-40%，且满足数据不出域要求。

一句话定位：GOAT 的默认主力，Sol 攻坚、Hy3 批量、Qwen 看图——GLM 干平时。

6.3 Tencent Hy3 — 极致便宜的批量机器

一句话：腾讯 2026-07 开源 MoE，299B/21B，Apache 2.0，地板价 + 满额的批量之王。

强项： - 地板价：$0.14/$0.58/$0.035 是四款中最便宜，比 GLM 便宜 10 倍，比 Sol 便宜 35-51 倍。$70 可跑 3-4 万次请求。 - 速度最快：75 tok/s，四款中最高吞吐。 - 开源可商用：Apache 2.0，21B active，比 GLM 更轻，单机部署门槛更低。 - 知识类小优：GPQA 90.4% 略胜 Qwen 27B，NL2Repo 亦占优。

弱项： - 智能分最低：42.2，比 GLM/Qwen 低约 10 分，复杂推理与长代理能力弱于前两者。 - 上下文 262K：仅为 GLM/Sol 的 1/4，长文档/超长对话场景需切片或换 GLM/Sol。 - 纯文本：无原生多模态，看图需求需切 Qwen。

适合谁： - 批量任务：格式化、迁包名、批量改文案、生成大量单测、数据清洗脚本。 - 成本敏感团队：把 Hy3 当“底座”，把省下的额度留给 Sol 做攻坚。

真实案例： - 案例 A：批量单测生成——某团队用 Hy3 对 800 个小模块批量生成 Vitest 单测，平均单次 Input 20K / Output 2K，$70 额度跑完全部仅消耗约 $12，剩余 $58 留作后续迭代。换 GLM 需 $90+，换 Sol 需 $400+。 - 案例 B：7 倍差距的来源——与 opencode-go 的 $60 档对比显示，同样 token 模式下 MiMo-V2.5（与 Hy3 同价位）月请求 150,400 vs Hy3 21,500 的差异，根因是模型单价与缓存策略，而 Hy3 在 GOAT 的满额使其“批量优势”最大化。

一句话定位：把脏活累活交给 Hy3，它便宜、快、够用，且 $70 几乎用不完。

6.4 Qwen 3.8 27B — 轻量旗舰的端侧答案

一句话：阿里 Qwen 3.8 家族的轻量版，262K 上下文 + 52.0 智能分 + 原生多模态，在“轻、快、能看图”上做到了平衡。

强项： - 轻量但智能不弱：52.0 分与 GLM-5.2（52.6）几乎持平，远超 Hy3（42.2），是四款中“小参数高智能”的代表。 - 原生多模态：文本+图像输入，四款中唯一适合“看图写代码/看图改前端”的轻量选择。 - 价格居中偏低：$0.40/$3.00 仅为 GLM 的 1/3 左右，$70 可跑 1.4-1.7 万次，耐用度仅次于 Hy3。 - 端侧友好传闻：社区称 27B 版本可在 ~17GB VRAM 单卡运行（待官方最终权重与许可证确认），适合端侧/私有化轻量部署。

弱项： - 上下文 262K：同 Hy3，小于 GLM/Sol。 - 编码实分待补：Qwen 3.8 家族的 Terminal-Bench 86.6 为自报分（阿里官方），GLM 的 82.7 为 AA audited；两者 3.9 分差距在误差带内，需独立复测。 - 生态新：2026-07 预览、08-03 GA，权重与许可证发布时间晚于 GLM，生产迁移需评估。

适合谁： - 前端/视觉相关编码：截图还原、设计稿转代码、文档解析、视频帧分析。 - 轻量自托管：单卡/端侧场景，GLM 太重、Hy3 不会看图时的折中。

真实案例： - 案例 A：设计稿转前端——某团队用 Qwen 3.8 27B 做“Figma 截图 → Tailwind 组件”，原生多模态使其在首轮还原度上高于 GLM/Hy3（后两者需外挂视觉模型），单次 Input 含 2 张 1024px 图 + 15K 文本，成本约为 GLM 的 40%。 - 案例 B：与 GLM 的互补——在 LLM-Stats 横评中，Qwen 27B 在 SWE-Bench/Terminal-Bench 上略胜 Hy3，适合“轻量但需一定工程能力”的场景；而 GLM 在更重的仓库级任务上仍更稳。两者可按“看图用 Qwen、重工程用 GLM”分工。

一句话定位：会看图的轻量 GLM 平替，便宜、够聪明、能看图，端侧友好。

8. 额度机制与窗口限制：别被 5 小时卡住

实战含义： - 用 Sol 时，$14/5h 仅够 180-240 次中等请求，连续让 Sol 跑 3 小时很容易触发限流；此时应切 GLM/Hy3 继续，或用额外 credits。 - 用 Hy3 时，$14/5h 可跑 6,400-7,600 次，几乎不会触发窗口——这就是 Hy3 作为“批量底座”的另一重优势。

额度会计规则： - credits = usage-value 单位：在 GOAT/Pro 上，满额模型 1 credit = $1 usage；非满额模型扣 credit 更快（例如 $20 额度的模型，$1 usage 扣 3.5 credits）。 - 先扣额外 credits：当你触发窗口限流时，额外 credits 会被优先消耗，从而“保护”你的月度额度不被窗口吞掉。

11. 最终建议与升级路径

11.1 一句话总结

  • Sol：最强，但最贵，适合“关键一击”。
  • GLM-5.2：最稳，日用默认，可自托管。
  • Hy3：最省，批量底座，$70 几乎用不完。
  • Qwen 27B：最轻，会看图，端侧友好。

最佳实践：GLM-5.2 日常 + Hy3 批量 + Sol 攻坚 + Qwen 看图。四池独立的设计，本意就是让你按任务切模型，而不是死守一个模型。

11.2 何时升级 Pro/Max

  • GOAT → Pro ($20/$80)：当你需要 Claude/GPT/Gemini 等闭源 Premium 模型，或 GOAT 的 $70/$60 池在某模型上频繁打满时。Pro 在四款满额上各多 $10（$70→$80，Hy3/Qwen/GLM/Sol 同步），并解锁更多 Premium 模型的 $20 池。
  • Pro → Max 10×/20× ($100/$150, $200/$300)：当你需要 Claude Opus/Fable、Fugu Ultra 等顶级 Premium 无限制，或日均请求 >1,000 次时。Max 的 $150/$300 为通用池（分 standard/premium 两池），不再按模型分 $20 小池。
