Unlimited-OCR AutoDL 部署与使用教程

这份教程记录如何在 AutoDL 云 GPU 服务器上部署并使用 baidu/Unlimited-OCR。适合本地电脑没有 NVIDIA GPU、但想用云服务器跑 OCR 的情况。

0. 实际部署复盘：这次是怎么跑通的

这一章按本次真实部署过程整理，方便下次复用，也方便教学时解释为什么这样选配置、为什么这样处理问题。

0.1 一开始想在 Mac 本地部署

本次最初目标是把 baidu/Unlimited-OCR 部署到本地电脑。检查本机环境后发现：

机器: MacBook Air
芯片: Apple M4
内存: 16GB
架构: arm64
GPU: Apple GPU / Metal
Python: 3.13.11
Docker: 未检测到

再看官方 README，发现官方推理要求是：

NVIDIA GPU
CUDA 12.9
Python 3.12.3
torch / torchvision / transformers
SGLang 或 Transformers CUDA 推理

官方 Transformers 示例里还有：

model = model.eval().cuda()

所以判断：Apple Silicon Mac 不能按官方方式原生部署。原因不是 Python 装不上，而是缺少 NVIDIA CUDA。Docker 也不能解决，因为 Mac Docker 里同样没有 NVIDIA CUDA GPU。

当时讨论过几个替代方案：

1. 用 Hugging Face Space 在线体验。
2. 租云 GPU 部署。
3. 云 GPU 跑服务，Mac 本地做客户端。
4. 等量化版本或社区适配。
5. 改用 PaddleOCR / RapidOCR 等轻量本地 OCR。

最后选择：在 AutoDL 上租 GPU 云服务器部署。

0.2 为什么没有选 RTX 2080 Ti 11GB

一开始看过一台配置：

GPU: RTX 2080 Ti
显存: 11GB
CPU: 12 核 Xeon Platinum 8255C
内存: 43GB
系统盘: 30GB
数据盘: 50GB
GPU 驱动: 510.60.02
CUDA: <= 11.6

这台没有选，原因是：

1. 11GB 显存太小，Unlimited-OCR 是 3B BF16 视觉语言模型，长上下文推理容易 OOM。
2. RTX 2080 Ti 是 Turing 架构，不适合 BF16 路线。
3. 驱动 510.60.02 太老，只到 CUDA 11.6。
4. 官方测试环境是 CUDA 12.9。
5. SGLang 参数里使用 fa3 attention backend，老卡和老 CUDA 不合适。
6. 系统盘 30GB，模型和缓存容易占满。

结论：这台机器即使能折腾，也不是稳定部署方案。

0.3 最后选的 AutoDL GPU 配置

后来选择了一台更合适的机器：

GPU: NVIDIA GeForce RTX 4080
显存: 32760MiB
CPU: 12 核 Xeon Platinum 8260
内存: 62GB
系统盘: 30GB
数据盘: 50GB，可扩容
GPU 驱动: 580.105.08
nvidia-smi CUDA Version: 13.0

虽然 nvidia-smi 显示 CUDA 13.0，但 PyTorch 环境实际是：

PyTorch: 2.8.0+cu128
torch.cuda.is_available(): True
torch.version.cuda: 12.8

这个组合是可以的，因为 NVIDIA 驱动向下兼容 CUDA 12.x。最终选的 AutoDL 镜像是：

PyTorch / 2.8.0 / Python 3.12 / Ubuntu 22.04 / CUDA 12.8

这个镜像接近官方要求：

官方: Python 3.12.3 + CUDA 12.9
实际: Python 3.12 + CUDA 12.8

0.4 第一次验证服务器环境

登录 AutoDL 后先执行：

nvidia-smi

看到 GPU 正常：

NVIDIA GeForce RTX 4080
32760MiB
Driver Version: 580.105.08
CUDA Version: 13.0

再执行：

python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.version.cuda)"

输出：

2.8.0+cu128
True
12.8

这一步很关键。只要 torch.cuda.is_available() 是 True，说明当前 PyTorch 可以调用 GPU。

0.5 为什么项目放在 /root/autodl-tmp

AutoDL 系统盘只有 30GB，模型、缓存、依赖很容易把系统盘塞满。

所以实际部署时采用：

项目目录: /root/autodl-tmp/Unlimited-OCR
模型目录: /root/autodl-tmp/models/Unlimited-OCR
Hugging Face 缓存: /root/autodl-tmp/huggingface
输出结果: /root/autodl-tmp/outputs_pdf 或 outputs_images

避免使用默认缓存：

/root/.cache/huggingface

因为默认位置可能占系统盘。

0.6 安装依赖时遇到的提示

安装依赖过程中，先装官方仓库里的 SGLang wheel：

uv pip install wheel/sglang-0.0.0.dev11416+g92e8bb79e-py3-none-any.whl

然后安装官方要求的 kernels 版本：

uv pip install kernels==0.11.7

安装时出现过：

- kernels==0.15.2
+ kernels==0.11.7

这表示环境里原来有 kernels 0.15.2，被降级成官方要求的 0.11.7。这是正常的。

还出现过：

Failed to hardlink files; falling back to full copy

这也不是错误。原因是 uv 的缓存目录和虚拟环境可能在不同文件系统，不能硬链接，只能复制。解决方式是设置：

export UV_LINK_MODE=copy

不过不设置也能用，只是会有 warning。

0.7 下载速度慢时改用镜像

安装 pymupdf 时下载比较慢，所以中断后改用清华 PyPI 镜像：

uv pip install pymupdf==1.27.2.2 -i https://pypi.tuna.tsinghua.edu.cn/simple

Python 包镜像和 Hugging Face 模型镜像是两回事：

PyPI 镜像: 下载 pymupdf、requests、huggingface_hub 等 Python 包
Hugging Face 镜像: 下载 baidu/Unlimited-OCR 模型权重

实际使用的 Hugging Face 镜像设置：

export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/root/autodl-tmp/huggingface
export TRANSFORMERS_CACHE=/root/autodl-tmp/huggingface/transformers

0.8 第一次启动服务时发生了什么

第一次直接启动：

python -m sglang.launch_server \
    --model baidu/Unlimited-OCR \
    --served-model-name Unlimited-OCR \
    --attention-backend fa3 \
    --page-size 1 \
    --mem-fraction-static 0.75 \
    --context-length 32768 \
    --enable-custom-logit-processor \
    --disable-overlap-schedule \
    --skip-server-warmup \
    --host 0.0.0.0 \
    --port 10000

启动时看到 tokenizer、配置文件下载成功，但后面出现：

Local HF snapshot ... has no files matching ['*.safetensors', '*.bin', '*.pt']; will attempt download.
Using model weights format ['*.safetensors']

这说明模型配置文件已经下载了，但权重文件还没有完整下载。

当时检查缓存目录：

du -sh /root/autodl-tmp/huggingface

看到只有：

4.1G /root/autodl-tmp/huggingface

判断模型还没完整下载。因为 Unlimited-OCR 是 3B BF16 模型，完整权重通常不止这一点。

0.9 改为手动下载模型

为了避免启动服务时边下载边加载导致卡住，改用手动下载模型。

一开始使用：

huggingface-cli download baidu/Unlimited-OCR \
    --local-dir /root/autodl-tmp/models/Unlimited-OCR \
    --local-dir-use-symlinks False

但新版 Hugging Face CLI 提示：

Warning: `huggingface-cli` is deprecated and no longer works. Use `hf` instead.

所以改成：

hf download baidu/Unlimited-OCR \
    --local-dir /root/autodl-tmp/models/Unlimited-OCR

这个经验很重要：现在新版环境要用 hf download，不要再用旧的 huggingface-cli download。

0.10 最终启动成功

模型准备好后，再次启动服务。最终看到：

Started server process [2721]
Waiting for application startup.
The server is fired up and ready to roll!
Application startup complete.
Uvicorn running on http://0.0.0.0:10000 (Press CTRL+C to quit)

这就表示服务启动成功。

这个窗口不要关，因为它就是 OCR 服务端。

0.11 如何判断 health 检查成功

新开一个终端，执行：

curl http://127.0.0.1:10000/health

服务窗口出现：

GET /health HTTP/1.1" 200 OK

这就算有返回，说明服务正常。

同时还可能看到：

Prefill batch, #new-seq: 1, #new-token: 1...

这是 SGLang 处理请求的日志，不是错误。

0.12 nvidia-smi 里的 sglang 进程说明

启动服务后执行：

nvidia-smi

看到过类似：

sglang::scheduler 6720MiB

这说明 SGLang 服务进程已经占用了 GPU 显存，是正常现象。刚启动时显存可能只有几 GB，后续加载和推理时会继续变化。

0.13 使用 infer.py 时复用已有服务

服务启动后，新开终端运行：

cd /root/autodl-tmp/Unlimited-OCR
source .venv/bin/activate

然后用 infer.py 处理 PDF：

python infer.py \
    --pdf /root/autodl-tmp/mba.pdf \
    --output_dir /root/autodl-tmp/outputs_pdf \
    --concurrency 1 \
    --image_mode base

当输出：

Reuse existing SGLang server: http://127.0.0.1:10000

说明 infer.py 没有再启动新服务，而是复用了已经启动的 10000 端口服务。这是正常的。

0.14 遇到 requests=0 的经验

处理一本 PDF 时，出现过：

Mode: pdf_pages, requests=0, concurrency=1, image_mode=base
Requests: 0/0
Total tokens: 0
Wall time: 0.00s

这不是 OCR 很快完成，而是没有任何页面被送进模型。也就是说输入阶段没有生成请求。

当时先检查 PDF 文件是否存在：

ls -lh /root/autodl-tmp/mba.pdf

结果：

-rw-r--r-- 1 root root 26M Jun 24 22:39 /root/autodl-tmp/mba.pdf

文件存在且大小 26M，说明不是空文件。下一步应该检查 PDF 页数、是否加密、是否能渲染第一页。

推荐排查命令：

python - <<'PY'
import fitz
pdf = "/root/autodl-tmp/mba.pdf"
doc = fitz.open(pdf)
print("pages:", doc.page_count)
print("encrypted:", doc.is_encrypted)
print("metadata:", doc.metadata)
doc.close()
PY

再测试能否转第一页图片：

python - <<'PY'
import fitz
pdf = "/root/autodl-tmp/mba.pdf"
doc = fitz.open(pdf)
page = doc[0]
pix = page.get_pixmap(matrix=fitz.Matrix(2, 2))
out = "/root/autodl-tmp/mba_page1.png"
pix.save(out)
print(out)
doc.close()
PY

如果能生成第一页，就可以先用图片目录方式测试，避免一次跑整本书。

0.15 本次部署形成的稳定流程

最终总结出的稳定流程是：

1. 不在 Mac 本地跑 Unlimited-OCR，改用 AutoDL GPU。
2. 不选 2080 Ti 11GB，选择 24GB+ 显存，实际使用 RTX 4080 32GB。
3. 镜像选择 PyTorch 2.8.0 / Python 3.12 / CUDA 12.8。
4. 用 nvidia-smi 和 torch.cuda.is_available() 验证 CUDA 可用。
5. 项目、模型、缓存都放 /root/autodl-tmp。
6. 使用 uv 创建虚拟环境。
7. 安装官方 SGLang wheel、kernels==0.11.7、pymupdf。
8. Python 包用清华 PyPI 镜像。
9. Hugging Face 模型用 hf-mirror.com。
10. 模型建议用 hf download 提前下载到本地目录。
11. 用本地模型路径启动 SGLang 服务。
12. 看到 Uvicorn running on http://0.0.0.0:10000 算启动成功。
13. 用 curl /health，看到 200 OK 算服务可用。
14. 新开终端激活同一个虚拟环境，用 infer.py 跑图片或 PDF。
15. 大 PDF 先不要整本跑，先转 1 页或几页测试。

这也是后面教程正文采用的部署方式。

1. 项目适用场景

baidu/Unlimited-OCR 是一个视觉语言 OCR / 文档解析模型，适合处理：

  • 扫描件图片 OCR
  • PDF 转图片后的多页识别
  • 中英文文档解析
  • 长文档内容提取

它不适合直接部署在 Apple Silicon Mac 上，因为官方推理路线依赖 NVIDIA GPU 和 CUDA。

2. 本地 Mac 为什么不适合直接跑

如果本机是 MacBook Air / MacBook Pro Apple Silicon，例如 M 系列芯片，通常会遇到这些问题：

  • 没有 NVIDIA GPU
  • 没有 CUDA
  • 官方示例代码使用 .cuda()
  • SGLang 路线依赖 CUDA / GPU attention backend
  • CPU 或 Apple MPS 强行跑可能极慢且容易不兼容

所以更推荐：模型跑在云服务器，本地电脑只负责上传文件、下载结果。

3. 云服务器推荐配置

推荐最低配置：

GPU: 24GB 显存起步
内存: 32GB 起步，64GB 更好
系统: Ubuntu 22.04
Python: 3.12
CUDA: 12.x
磁盘: 100GB 以上更稳

推荐 GPU：

RTX 4090 24GB
RTX 4080 32GB
A10 24GB
A5000 24GB
A100 40GB

不推荐：

RTX 2080 Ti 11GB
CUDA 11.x
CPU-only
Apple / AMD GPU

原因是 Unlimited-OCR 是 3B BF16 视觉语言模型，官方还使用长上下文，11GB 显存很容易不够。

4. 已验证可用环境示例

本次部署使用的环境：

GPU: NVIDIA GeForce RTX 4080
显存: 32760MiB
Driver: 580.105.08
CUDA Version from nvidia-smi: 13.0
PyTorch: 2.8.0+cu128
torch.cuda.is_available(): True
torch.version.cuda: 12.8
Python: 3.12
Ubuntu: 22.04

AutoDL 镜像可以选择：

PyTorch / 2.8.0 / Python 3.12 / Ubuntu 22.04 / CUDA 12.8

5. 登录服务器后先检查环境

进入 AutoDL 终端后，先检查 GPU：

nvidia-smi

再检查 PyTorch：

python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.version.cuda)"

理想输出类似：

2.8.0+cu128
True
12.8

只要 torch.cuda.is_available() 是 True，说明 CUDA 可用。

6. 进入数据盘

不要把模型和项目放系统盘。AutoDL 系统盘通常只有 30GB，容易爆。

进入数据盘：

cd /root/autodl-tmp

7. 下载项目

git clone https://github.com/baidu/Unlimited-OCR.git
cd Unlimited-OCR

8. 创建虚拟环境

如果没有 uv，先安装：

pip install -i https://pypi.tuna.tsinghua.edu.cn/simple uv

创建 Python 3.12 虚拟环境：

uv venv --python 3.12
source .venv/bin/activate

激活成功后，命令行前面通常会出现：

(Unlimited-OCR)

9. 设置镜像和缓存目录

建议设置 Hugging Face 镜像，并把模型缓存放到数据盘：

export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/root/autodl-tmp/huggingface
export TRANSFORMERS_CACHE=/root/autodl-tmp/huggingface/transformers
export UV_LINK_MODE=copy

说明：

  • HF_ENDPOINT 用于 Hugging Face 模型下载镜像。
  • HF_HOME 把模型缓存放到数据盘。
  • TRANSFORMERS_CACHE 避免占用系统盘。
  • UV_LINK_MODE=copy 可以消除 uv 跨文件系统 hardlink 警告。

10. 安装依赖

在项目目录 /root/autodl-tmp/Unlimited-OCR 下执行：

uv pip install wheel/sglang-0.0.0.dev11416+g92e8bb79e-py3-none-any.whl
uv pip install kernels==0.11.7 -i https://pypi.tuna.tsinghua.edu.cn/simple
uv pip install pymupdf==1.27.2.2 requests huggingface_hub -i https://pypi.tuna.tsinghua.edu.cn/simple

如果看到类似提示：

Failed to hardlink files; falling back to full copy

这不是错误。它只是说 uv 不能用硬链接安装，改成普通复制，不影响使用。

11. 下载模型

模型可以在第一次启动服务时自动下载，也可以提前手动下载。推荐手动下载，更稳定。

新版 Hugging Face CLI 使用 hf，不是 huggingface-cli download。

执行：

export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/root/autodl-tmp/huggingface

hf download baidu/Unlimited-OCR \
    --local-dir /root/autodl-tmp/models/Unlimited-OCR

如果下载中断，重复同一个命令即可。它会跳过已完成文件或继续下载。

下载完成后，模型目录是：

/root/autodl-tmp/models/Unlimited-OCR

12. 启动服务

进入项目目录并激活虚拟环境：

cd /root/autodl-tmp/Unlimited-OCR
source .venv/bin/activate

使用本地模型路径启动：

python -m sglang.launch_server \
    --model /root/autodl-tmp/models/Unlimited-OCR \
    --served-model-name Unlimited-OCR \
    --attention-backend fa3 \
    --page-size 1 \
    --mem-fraction-static 0.75 \
    --context-length 32768 \
    --enable-custom-logit-processor \
    --disable-overlap-schedule \
    --skip-server-warmup \
    --host 0.0.0.0 \
    --port 10000

如果没有提前下载模型，也可以直接用 Hugging Face 模型名：

python -m sglang.launch_server \
    --model baidu/Unlimited-OCR \
    --served-model-name Unlimited-OCR \
    --attention-backend fa3 \
    --page-size 1 \
    --mem-fraction-static 0.75 \
    --context-length 32768 \
    --enable-custom-logit-processor \
    --disable-overlap-schedule \
    --skip-server-warmup \
    --host 0.0.0.0 \
    --port 10000

启动成功时，会看到：

The server is fired up and ready to roll!
Uvicorn running on http://0.0.0.0:10000

这个终端不要关。它就是 OCR 后端服务。

13. 常见启动日志说明

如果看到：

Ignore import error when loading sglang.srt.multimodal.processors.gemma4

通常可以忽略。SGLang 在扫描其他模型组件，但当前不是运行 Gemma4。

如果看到：

torch_dtype is deprecated! Use dtype instead!

这只是警告，不影响启动。

如果看到：

Local HF snapshot ... has no files matching ['*.safetensors']

说明模型权重还没完整下载，它会尝试继续下载。可以用下面命令看缓存目录大小：

du -sh /root/autodl-tmp/huggingface

如果目录大小持续增长，说明还在下载。

14. 测试服务是否正常

另开一个 AutoDL 终端，不要关闭服务终端。

执行：

curl http://127.0.0.1:10000/health

如果服务端日志出现：

GET /health HTTP/1.1" 200 OK

就说明服务正常。

15. 每次使用前的固定步骤

以后每次新开终端使用，都先执行：

cd /root/autodl-tmp/Unlimited-OCR
source .venv/bin/activate
curl http://127.0.0.1:10000/health

如果健康检查正常，就可以开始 OCR。

16. 识别图片目录

准备图片目录，例如：

/root/autodl-tmp/images

这个路径不是固定要求，只要目录真实存在即可。建议使用绝对路径，避免当前终端目录不同导致找不到文件。

里面可以放：

001.jpg
002.png
003.jpeg

运行：

python infer.py \
    --image_dir /root/autodl-tmp/images \
    --output_dir /root/autodl-tmp/outputs_images \
    --concurrency 1 \
    --image_mode gundam

结果目录：

/root/autodl-tmp/outputs_images

输出目录也可以自定义，例如：

/root/autodl-tmp/outputs/my_images

如果目录不存在，通常程序会自动创建；如果报错，再手动创建即可。

单张图片建议使用：

--image_mode gundam

17. 识别 PDF

假设 PDF 路径是：

/root/autodl-tmp/mba.pdf

这个路径不是固定要求。--pdf 后面只需要填真实存在的 PDF 路径即可，推荐使用绝对路径。

例如这些都可以：

/root/autodl-tmp/mba.pdf
/root/autodl-tmp/books/mba.pdf
/root/autodl-tmp/input/document.pdf

运行：

python infer.py \
    --pdf /root/autodl-tmp/mba.pdf \
    --output_dir /root/autodl-tmp/outputs_pdf \
    --concurrency 1 \
    --image_mode base

结果目录：

/root/autodl-tmp/outputs_pdf

输出路径也不是固定要求。--output_dir 后面可以填任意你想保存结果的目录。

例如一本书一个输出目录：

python infer.py \
    --pdf /root/autodl-tmp/books/mba.pdf \
    --output_dir /root/autodl-tmp/outputs/mba \
    --concurrency 1 \
    --image_mode base

如果路径里有空格或特殊字符，需要加引号：

python infer.py \
    --pdf "/root/autodl-tmp/books/my book.pdf" \
    --output_dir "/root/autodl-tmp/outputs/my book" \
    --concurrency 1 \
    --image_mode base

PDF / 多页图片建议使用：

--image_mode base

先用：

--concurrency 1

确认稳定后再考虑提高并发。

18. 如果 infer.py 显示 requests=0

如果运行 PDF 后输出：

Mode: pdf_pages, requests=0
Requests: 0/0

21. 端口占用问题

如果已经手动启动了服务，再运行 infer.py 时可能出现端口占用。

如果 infer.py 输出：

Reuse existing SGLang server: http://127.0.0.1:10000

说明它复用了当前服务，这是正常的。

如果报：

address already in use
port 10000 already in use

说明它试图再启动一个服务，和已有服务冲突。解决方法：

方法一：保留当前服务，改用 API 调用脚本。
方法二：按 Ctrl+C 停掉当前服务，再让 infer.py 自己启动。

23. 常见问题速查

23.1 服务启动后没有 Uvicorn

如果还没看到：

Uvicorn running on http://0.0.0.0:10000

说明服务还没启动完成。检查模型是否还在下载：

du -sh /root/autodl-tmp/huggingface

如果大小持续增长，继续等。如果长期不变，建议手动下载模型。

23.2 health 有 200 OK 算成功吗

算成功。

日志类似：

GET /health HTTP/1.1" 200 OK

说明服务健康检查通过。

23.3 nvidia-smi 显示 sglang 占显存正常吗

正常。比如：

sglang::scheduler 6720MiB

说明 SGLang 进程已经占用 GPU。

23.4 PyMuPDF 下载慢怎么办

使用清华 PyPI 镜像：

uv pip install pymupdf==1.27.2.2 -i https://pypi.tuna.tsinghua.edu.cn/simple

23.5 huggingface-cli download 不能用怎么办

新版命令改成：

hf download baidu/Unlimited-OCR --local-dir /root/autodl-tmp/models/Unlimited-OCR

24. 最终建议

最稳的使用方式：

1. AutoDL 选择 PyTorch 2.8.0 / Python 3.12 / CUDA 12.8 镜像。
2. 模型和缓存全部放 /root/autodl-tmp。
3. 手动下载模型到 /root/autodl-tmp/models/Unlimited-OCR。
4. 用 SGLang 启动 OCR 服务。
5. 新开终端使用 infer.py 处理图片或 PDF。
6. PDF 先用 concurrency=1 和 image_mode=base 测试。

如果只是测试，先不要跑整本书。先跑 1 页或几页，确认输出效果和速度后，再批量处理完整 PDF。
