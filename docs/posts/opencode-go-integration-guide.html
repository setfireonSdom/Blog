背景

OpenCode Go 是什么

OpenCode Go 是 OpenCode 团队推出的低价订阅计划：首月 $5，之后 $10/月，提供对一批精选开源编码模型的稳定访问。模型托管在美、欧、新加坡，延迟低，零数据留存政策。

Qwen Coding Agent 是什么

Qwen Coding Agent（通义千问编码助手）是阿里推出的终端 AI 编码助手，基于 @qwen-code/qwen-code npm 包。它的配置目录是 ~/.qwen/，核心配置文件是 settings.json。

为什么接入

Go 套餐里的 DeepSeek V4 Pro / Flash 编码能力强、价格极低（Flash 免费用量极大），比 Qwen 自带模型性价比更高。通过自定义 Provider 接入后，可以在 Qwen Coding Agent 里直接使用这些模型。

前置条件

1. 注册 OpenCode 并订阅 Go 套餐

访问 opencode.ai/auth，注册账号 → 进入控制台 → 订阅 OpenCode Go → 获取 API Key。

API Key 格式类似：sk-mFvWnseb...（以 sk- 开头的长字符串）。

2. 确认 Qwen Coding Agent 已安装

qwen --version
# 或
which qwen

3. 确认 settings.json 位置

配置文件路径：

~/.qwen/settings.json

Windows 用户对应的路径为 %USERPROFILE%\.qwen\settings.json（通常在 C:\Users\<用户名>\.qwen\settings.json）。

如果是工作区级别的配置，则工作区目录下也有自己的 settings.json。本文以全局配置为例。

核心概念：两种 API 端点

OpenCode Go 的模型分两种 API 协议，使用不同的端点：

协议 端点 模型
OpenAI 兼容 https://opencode.ai/zen/go/v1/chat/completions DeepSeek V4 Pro, DeepSeek V4 Flash, GLM-5, GLM-5.1, Kimi K2.5, Kimi K2.6, MiMo V2.5, MiMo V2.5 Pro
Anthropic 兼容 https://opencode.ai/zen/go/v1/messages Qwen3.6 Plus, Qwen3.7 Max, MiniMax M2.5, MiniMax M2.7, MiniMax M3

关键结论：Qwen Coding Agent 目前只支持 OpenAI 兼容协议（security.auth.selectedType: "openai"），因此只能接入表格第一组的模型。如果你想用 Qwen3.6 Plus 或 MiniMax 系列，需要通过另一套协议，本文暂不涉及。

配置步骤

步骤 1：找到并打开 settings.json

vim ~/.qwen/settings.json

步骤 2：确认 JSON 结构

一个完整的 settings.json 包含以下主要板块：

{
  "$version": 4,
  "security": { "auth": { "selectedType": "openai" } },
  "model": { "name": "..." },
  "env": { "...": "你的 API Key" },
  "modelProviders": {
    "openai": [ /* 模型列表 */ ]
  }
}

你需要修改的是 env 和 modelProviders 两个板块。

步骤 3：在 env 中添加 API Key

在 env 对象中添加一个键值对。键名可以完全自定义（比如你可以用 MY_OPENCODE_KEY 这样简短的名字），唯一的要求是与后面 modelProviders 中引用的 envKey 完全一致。值为你的 OpenCode Go API Key：

"env": {
  "QWEN_CUSTOM_API_KEY_OPENAI_HTTPS_OPENCODE_AI_ZEN_GO_V1_D6F6AD32A9A7": "sk-你的Go套餐APIKey"
}

命名参考：上面示例中的长键名是 Qwen 通过 UI 界面自动生成的，遵循命名规则 QWEN_CUSTOM_API_KEY_{selectedType}_{baseUrl大写转下划线}_{随机后缀}。如果你自己手动编辑 settings.json，完全可以用任何你喜欢的键名（如 GO_API_KEY），只要能保证 env 和 modelProviders 中的键名一致即可。

步骤 4：在 modelProviders.openai 中添加模型

在 modelProviders 的 openai 数组中，为每个模型添加一个条目：

"modelProviders": {
  "openai": [
    {
      "id": "deepseek-v4-flash",
      "name": "deepseek-v4-flash",
      "baseUrl": "https://opencode.ai/zen/go/v1",
      "envKey": "QWEN_CUSTOM_API_KEY_OPENAI_HTTPS_OPENCODE_AI_ZEN_GO_V1_D6F6AD32A9A7"
    },
    {
      "id": "deepseek-v4-pro",
      "name": "deepseek-v4-pro",
      "baseUrl": "https://opencode.ai/zen/go/v1",
      "envKey": "QWEN_CUSTOM_API_KEY_OPENAI_HTTPS_OPENCODE_AI_ZEN_GO_V1_D6F6AD32A9A7"
    }
  ]
}

各字段说明

字段 含义 注意事项
id 模型标识，对应 Go API 的 model 参数 必须与 Go 的 model ID 完全一致（见附录清单）
name 在 Qwen 界面中显示的模型名称 可以与 id 相同，也可以自定义
baseUrl API 基础地址 只写到 /v1，不要带 /chat/completions（这是最重要的坑，详见下文）
envKey 指向 env 对象中存储 API Key 的键名 必须与 env 中的键名完全一致

步骤 5：设置默认模型（可选）

修改 model.name 来指定默认模型：

"model": {
  "name": "deepseek-v4-pro"
}

步骤 6：完整配置示例

以下是接入 DeepSeek V4 Pro 和 DeepSeek V4 Flash 的完整配置：

{
  "$version": 4,
  "security": {
    "auth": {
      "selectedType": "openai"
    }
  },
  "model": {
    "name": "deepseek-v4-pro"
  },
  "env": {
    "QWEN_CUSTOM_API_KEY_OPENAI_HTTPS_OPENCODE_AI_ZEN_GO_V1_D6F6AD32A9A7": "sk-你的Go套餐APIKey"
  },
  "modelProviders": {
    "openai": [
      {
        "id": "deepseek-v4-flash",
        "name": "deepseek-v4-flash",
        "baseUrl": "https://opencode.ai/zen/go/v1",
        "envKey": "QWEN_CUSTOM_API_KEY_OPENAI_HTTPS_OPENCODE_AI_ZEN_GO_V1_D6F6AD32A9A7"
      },
      {
        "id": "deepseek-v4-pro",
        "name": "deepseek-v4-pro",
        "baseUrl": "https://opencode.ai/zen/go/v1",
        "envKey": "QWEN_CUSTOM_API_KEY_OPENAI_HTTPS_OPENCODE_AI_ZEN_GO_V1_D6F6AD32A9A7"
      }
    ]
  }
}

深入理解 settings.json

请求是如何发出的

Qwen Coding Agent 使用 OpenAI 兼容的 HTTP 客户端发起请求。请求 URL 的拼接规则为：

最终请求 URL = baseUrl + "/chat/completions"

所以： - baseUrl: "https://opencode.ai/zen/go/v1" → 请求 https://opencode.ai/zen/go/v1/chat/completions ✅ - baseUrl: "https://opencode.ai/zen/go/v1/chat/completions" → 请求 https://opencode.ai/zen/go/v1/chat/completions/chat/completions ❌

API Key 从 env[envKey] 中读取，通过 HTTP Header Authorization: Bearer <key> 发送。

envKey 的命名机制

关键原则：envKey 只是一个引用名，你可以随意命名。 它必须满足的唯一条件是 modelProviders 中的 envKey 和 env 对象中的键名完全一致（大小写敏感）。

Qwen Coding Agent 通过 UI 界面自动生成 envKey 时的规则是：

QWEN_CUSTOM_API_KEY_{selectedType大写}_{baseUrl去掉协议和斜杠转为下划线}_{hash后缀}

例如：

QWEN_CUSTOM_API_KEY_OPENAI_HTTPS_OPENCODE_AI_ZEN_GO_V1_D6F6AD32A9A7
  • OPENAI — security.auth.selectedType
  • HTTPS_OPENCODE_AI_ZEN_GO_V1 — baseUrl 去掉 https:// 和 /，点转下划线
  • D6F6AD32A9A7 — 随机 hash 后缀

手动编辑时：你完全可以不用上面这种长键名，改用 GO_API_KEY、MY_OPENCODE_TOKEN 等简短名称。只要 modelProviders 里的 envKey 和 env 里的键名一致就行。推荐用简短名称，不容易打错，排查问题时也更直观。

验证方法

方法 1：API 直接测试

用 curl 验证模型和 API Key 是否可用：

# 测试 deepseek-v4-flash
curl -s https://opencode.ai/zen/go/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-你的APIKey" \
  -d '{"model":"deepseek-v4-flash","messages":[{"role":"user","content":"say hi"}]}'

# 测试 deepseek-v4-pro
curl -s https://opencode.ai/zen/go/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-你的APIKey" \
  -d '{"model":"deepseek-v4-pro","messages":[{"role":"user","content":"say hi"}]}'

返回 HTTP 200 且 JSON 中有正常的 choices 即为成功。

方法 2：查看可用模型列表

curl -s https://opencode.ai/zen/go/v1/models | python3 -m json.tool

这会列出 Go 套餐中所有可用模型的 ID，确认你要配置的模型在列表中。

方法 3：通过 Qwen Coding Agent 实际对话

  1. 重启 Qwen Coding Agent
  2. 输入 /model 查看可用模型列表，确认新模型出现
  3. 选择模型，发送一条简单对话，确认正常回复

方法 4：查看 Qwen 调试日志

cat ~/.qwen/debug/latest

搜索 OPENAI_ERROR 或 ERROR_REPORT，如有异常会在此记录。正常情况日志中不会有这些错误。

踩坑记录（必读）

坑 1：baseUrl 重复拼接 /chat/completions ⚠️ 最常见

现象：配置完成后对话报错 API Error: 404，返回 opencode.ai 的 404 HTML 页面。

原因：Qwen Coding Agent 的 OpenAI 客户端会自动在 baseUrl 后面追加 /chat/completions。如果 baseUrl 已经包含了 /chat/completions，最终请求 URL 变成：

https://opencode.ai/zen/go/v1/chat/completions/chat/completions

这是一个不存在的路径，opencode.ai 的 web 服务器返回 404 HTML 页面。

解决方案：baseUrl 只写到 /v1：

❌ "baseUrl": "https://opencode.ai/zen/go/v1/chat/completions"
✅ "baseUrl": "https://opencode.ai/zen/go/v1"

坑 2：envKey 不匹配

现象：配置了模型但 Qwen 提示 API Key 无效或未找到。

原因：modelProviders 中的 envKey 与 env 对象中的键名不一致。这两个必须完全匹配，包括大小写和下划线。

解决方案：用编辑器搜索确认两个字符串完全一致。最简单的方法是：先在 env 中定义好 API Key 的键名，然后在 modelProviders 中复制粘贴该键名作为 envKey。

排查技巧：

# 检查 env 中有哪些 key
cat ~/.qwen/settings.json | python3 -c "import json,sys; d=json.load(sys.stdin); print(list(d.get('env',{}).keys()))"

# 检查 modelProviders 中引用了哪些 envKey
cat ~/.qwen/settings.json | python3 -c "import json,sys; d=json.load(sys.stdin); [print(p.get('envKey')) for p in d.get('modelProviders',{}).get('openai',[])]"

两个输出应该能对应上。

坑 3：model id 写错

现象：API 返回 404 或 model not found。

原因：id 字段必须与 OpenCode Go API 中的 model ID 完全一致，不能自创。

解决方案：查询官方模型列表确认正确 ID：

curl -s https://opencode.ai/zen/go/v1/models | python3 -c "import json,sys; [print(m['id']) for m in json.load(sys.stdin)['data']]"

坑 4：Anthropic 协议的模型无法接入

现象：配置 Qwen3.6 Plus、Qwen3.7 Max、MiniMax 系列后无法使用。

原因：这些模型在 Go 套餐中使用的是 Anthropic 兼容协议（/v1/messages 端点），而 Qwen Coding Agent 的 modelProviders 目前只支持 OpenAI 兼容协议（selectedType: "openai"）。

当前限制：只能接入使用 /v1/chat/completions 端点的模型（OpenAI 兼容协议那组）。

坑 5：API Key 未激活

现象：API 返回 401 Unauthorized。

原因： 1. 尚未在 opencode.ai/auth 订阅 Go 套餐 2. API Key 已过期或已撤销 3. API Key 是 Zen 的 key 而非 Go 的 key

解决方案：登录 opencode.ai 控制台，确认 Go 订阅状态为 Active，重新生成 API Key 并更新配置。

坑 6：Go 套餐用量超限

Go 套餐有使用限制，不同时间窗口的用量上限如下：

  • 5 小时窗口：$12 用量上限（即每 5 小时内最多消耗 $12 的 API 额度，约为 2-3 小时的实际使用量）
  • 每周窗口：$30 用量上限
  • 每月窗口：$60 用量上限

超出后会返回错误。解决方法： 1. 等待限制窗口重置 2. 在 opencode.ai/auth 控制台中启用 “Use balance” 选项，超出后用 Zen 余额兜底

总结

  1. 获取 OpenCode Go API Key
  2. 在 ~/.qwen/settings.json 的 env 中添加 API Key
  3. 在 modelProviders.openai 中添加模型条目
  4. baseUrl 写到 /v1，不要带 /chat/completions
  5. envKey 必须与 env 中的键名一致
  6. id 必须与 Go 模型的 model ID 一致
  7. 重启 Qwen Coding Agent，/model 切换模型验证

按照以上步骤操作，5 分钟内即可完成接入。
