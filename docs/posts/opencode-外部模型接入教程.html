OpenCode 外部模型接入教程

基于 opencode 1.16.2 实测，2026-06

1. 配置文件在哪

OpenCode 的配置文件叫 opencode.json（或 opencode.jsonc，支持注释），有两个位置：

作用域 路径 用途
全局 ~/.config/opencode/opencode.jsonc 对本机所有项目生效
项目 项目根目录 /opencode.json（和 .git 同级） 只对当前项目生效

两个文件可以同时存在（项目级覆盖全局级）。本文以修改全局配置为例。

2. 接入外部模型的两种方式

方式一：内置提供商（最简单）

OpenCode 预装了 75+ 主流提供商。在 TUI 中输入 /connect，搜索选择厂商（OpenAI、Anthropic、DeepSeek、Groq 等），粘贴 API Key 即可。无需手动写配置。

方式二：自定义提供商（最灵活）

适合这些场景：

  • 用 OpenRouter、9Router 等路由网关
  • 用 Ollama、LM Studio 等本地模型
  • 用任何提供 OpenAI 兼容接口的服务

核心原理：只要服务商的 API 兼容 OpenAI 的 /v1/chat/completions 格式，就可以用 @ai-sdk/openai-compatible 这个适配器接入。

3. 自定义 Provider 核心模板

下面是一个填空模板，除 【】 标注的部分外，其余一律不动。

{
  "$schema": "https://opencode.ai/config.json",

  "provider": {
    "【1】": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "【3】",
      "options": {
        "baseURL": "【4】"
      },
      "models": {
        "【2】": {
          "name": "【3】"
        }
      }
    }
  }
}

5 个空怎么填

编号 字段 填什么 谁给你
1 提供商 ID 自己起英文名，如 9router 你自己起
2 模型 ID 模型名称，如 deepseek-chat 服务商提供（在服务商文档或 /v1/models 端点查看）
3 显示名 界面上的名字，如 DeepSeek V4 Pro 你自己起
4 baseURL API 端点地址 服务商提供
可选 apiKey API 密钥 服务商后台生成（本地服务如 9Router/Ollama 通常不需要）

【1】 和 【3】 跟服务商无关，纯标识用途，自己随意命名即可。

4. 两个必要条件（踩坑总结）

条件一：models 块必须写

opencode 1.16.2 要求自定义 provider 必须至少定义 models，否则整个 provider 会被静默跳过。

对比验证方法：查看启动日志：

ls -t ~/.local/share/opencode/log/ | head -1 | xargs tail -5

看到 provider providerID=你的ID found 即为成功加载。

条件二：@ai-sdk/openai-compatible 包必须能被找到

无需手动安装。只要你的系统上有任何 Node 全局包依赖了它，Node.js 的模块解析机制就能自动找到（npm list -g @ai-sdk/openai-compatible 可验证）。

如果系统上完全没有这个包，执行：

npm install -g @ai-sdk/openai-compatible

5. 完整示例：9Router 接入 DeepSeek V4 Pro

假设你已安装 9Router（npm install -g 9router && 9router），它监听在 localhost:20128，提供 OpenAI 兼容接口。9Router 是本地服务，不需要 apiKey。

已知信息： - 端点：http://localhost:20128/v1 - 模型 ID：cmc/deepseek/deepseek-v4-pro

填完的配置：

{
  "$schema": "https://opencode.ai/config.json",

  "provider": {
    "9router": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "9Router",
      "options": {
        "baseURL": "http://localhost:20128/v1"
      },
      "models": {
        "cmc/deepseek/deepseek-v4-pro": {
          "name": "DeepSeek V4 Pro"
        }
      }
    }
  }
}

保存后完全退出 opencode 再重启，输入 /models 即可看到 9Router 分类下的模型。

6. 设置默认模型（可选）

在配置顶层加 model 字段，格式为 providerID/模型ID：

{
  "$schema": "https://opencode.ai/config.json",
  "model": "9router/cmc/deepseek/deepseek-v4-pro",

  "provider": {
    "9router": {
      // ... 同上
    }
  }
}

启动 opencode 后自动选中该模型。

7. 多个 Provider 怎么写

provider 是一个 JSON 对象，每个提供商是一个键值对。加新的不要替换旧的，追加即可，键值对之间用逗号隔开。

{
  "$schema": "https://opencode.ai/config.json",

  "provider": {

    // Provider 一
    "9router": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "9Router",
      "options": {
        "baseURL": "http://localhost:20128/v1"
      },
      "models": {
        "cmc/deepseek/deepseek-v4-pro": {
          "name": "DeepSeek V4 Pro"
        }
      }
    },

    // Provider 二（注意前面有逗号）
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama 本地",
      "options": {
        "baseURL": "http://localhost:11434/v1"
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen3 Coder 本地"
        }
      }
    }
  }
}

要点：在上一个 } 后面加逗号，然后写下一个 provider。

8. 一个 Provider 多个模型怎么写

同理，models 也是一个 JSON 对象，每加一个模型就追加一个键值对。

"9router": {
  "npm": "@ai-sdk/openai-compatible",
  "name": "9Router",
  "options": {
    "baseURL": "http://localhost:20128/v1"
  },
  "models": {

    // 模型一
    "cmc/deepseek/deepseek-v4-pro": {
      "name": "DeepSeek V4 Pro"
    },

    // 模型二（注意前面有逗号）
    "cmc/xiaomi/mimo-v2.5": {
      "name": "MIMO V 2.5"
    }
  }
}

谨慎：JSONC 的 models 块最后一项不要加尾逗号（,}），否则可能导致解析失败。

结构关系

opencode.jsonc
  └── provider (对象)
        ├── provider-A (对象)
        │     └── models (对象)
        │           ├── 模型1 (对象)
        │           ├── 模型2 (对象)
        │           └── ...
        ├── provider-B (对象)
        │     └── models (对象)
        │           └── ...
        └── ...

9. 运行验证

  1. 确保你的模型服务在运行（如果是本地服务如 9Router、Ollama）
  2. 完全退出 opencode，重新启动（配置只在启动时加载）
  3. 输入 /models，在列表里找到你配的 provider 和模型
  4. 选中即可使用

10. /models 列表的 UI 行为

一个容易困惑的设计细节：

当前正在使用的模型不会出现在它所属的 provider 分类下，只会出现在 “Recent” 中。

这意味着：如果你的自定义 provider 只配了 1~2 个模型，用完一遍后 provider 分类就会变空（全部移到 Recent 了）。这不是 bug，是设计如此。

对比：opencode-go 等内置 provider 下面有十几二十个模型，不可能全部用完，所以分类永远存在。

解决办法：要么接受在 Recent 里选模型（功能不受影响），要么多配几个模型让分类里永远有剩余。

11. 常见问题

Q: API Key 不想写在配置文件里怎么办？

用环境变量代替：

"apiKey": "{env:MY_API_KEY}"

然后在终端里 export MY_API_KEY=sk-xxx 或写入 ~/.zshrc。

Q: 本地服务（9Router/Ollama 等）需要 apiKey 吗？

不需要。baseURL 指向 localhost 时，apiKey 字段可以直接省略。

Q: 模型 ID 在哪查看？

  • 内置服务商：使用 /models 命令查看
  • 本地服务（如 9Router/Ollama）：访问 http://localhost:PORT/v1/models
  • 服务商文档

Q: 原来用 /connect 添加的提供商需要写进配置文件吗？

不需要。/connect 会自动把凭证存到 ~/.local/share/opencode/auth.json，provider 和 models 在启动时自动加载。配置文件只用于自定义 provider 或覆盖默认设置。

Q: 配置里的 npm 字段是什么意思？

"npm": "@ai-sdk/openai-compatible" 指定使用哪个 AI SDK 适配器包。只要是提供 OpenAI 兼容接口的服务，都用这个。你无需手动安装它——Node.js 的模块解析会自动找到。

Q: 改完配置后模型不出现怎么办？

  1. 确认完全退出了 opencode 再重启（不是切 session）
  2. 检查 models 块是否存在——没有它，整个 provider 被静默跳过
  3. 查看启动日志确认 provider 是否加载：ls -t ~/.local/share/opencode/log/ | head -1 | xargs grep provider
  4. 检查 JSON 语法是否有误（尾逗号、引号配对）
