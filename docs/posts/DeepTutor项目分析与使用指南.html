DeepTutor 项目分析与使用指南

项目地址：HKUDS/DeepTutor
分析基准：2026 年 8 月 10 日，main 分支，v1.5.11
一句话结论：它是一套可以自己部署的 AI 学习工作台，适合拿自己的教材、论文和笔记做问答、解题、出题、研究和写作，但需要自己准备大模型，并承担模型费用、部署和数据安全方面的责任。

先说人话：它到底是什么

DeepTutor 可以理解成“把 ChatGPT、个人资料库、错题本、研究助手和写作工具装进同一个网站”。

你可以先上传教材、讲义、PDF、Word、PPT 等资料，让它建立知识库。以后提问时，它不只是凭大模型自己的记忆回答，还可以先从你的资料里找相关内容，再结合模型生成答案。这种“先查资料，再回答”的做法通常叫 RAG。

它又不只做资料问答。你还可以让它：

  • 一步步讲题，而不是只扔出答案；
  • 根据教材生成选择题、问答题和练习计划；
  • 搜索网页或论文，整理成带引用的研究报告；
  • 把难懂的概念做成图表、流程图、动画或交互页面；
  • 保存笔记、错题、聊天记录和长期学习偏好；
  • 根据资料生成一套可以边读边问、边读边测的“交互式书”；
  • 在 Markdown 写作台里改报告、写教程、整理学习笔记；
  • 接入 Claude Code、Codex、Gemini CLI、MCP 工具和聊天软件机器人。

所以，它更像一个“AI 学习操作台”，不是一个单独的聊天机器人。

它最有用的地方

1. 围绕自己的材料学习

这是最实用的功能。

例如你有一本 600 页的机器学习教材、一批课程 PPT 和老师发的习题。可以把它们放进同一个知识库，然后这样问：

只根据我上传的教材，解释交叉熵和 KL 散度的关系，并指出对应章节。
根据第 3 章到第 5 章给我出 10 道题，先不要公布答案，我答完后再逐题讲。
比较讲义和教材对过拟合的解释，有冲突的地方列出来。

与直接把一份 PDF 临时丢进普通聊天窗口相比，DeepTutor 的优点是资料可以长期保存，并在聊天、写作、出题、Book 和 Partner 等多个功能中重复使用。

2. 把“问答案”变成“练习和反馈”

它提供 Quiz、Solve 和 Mastery Path 等学习模式。说白了，就是让模型不只回答问题，还能出题、检查答案、补薄弱点并安排下一轮练习。

例如备考时可以让它：

  1. 根据指定章节出一组题；
  2. 记录你的答案；
  3. 解释错因；
  4. 把错题放进题库；
  5. 针对薄弱知识点继续出题。

不过要注意，自动批改仍然是模型判断，不能当作权威评分。数学、法律、医学和工程安全等高风险内容，必须人工复核。

3. 做资料调研和报告

Research 模式可以调用网页搜索、论文搜索和知识库，生成带来源的报告。Co-Writer 则像一个带 AI 的 Markdown 编辑器：选中一段，要求扩写、缩写、改写或补证据，修改内容会以差异形式展示，确认后才写入。

适合这些工作：

  • 课程论文的前期资料整理；
  • 文献主题归纳；
  • 技术路线对比；
  • 教案和教程编写；
  • 从多份内部文档整理说明书。

引用能帮助核查，但不代表内容自动正确。最终仍应打开原文确认，不要只看模型生成的引用列表。

4. 建立长期学习档案

DeepTutor 的 Memory 不是完全藏在数据库里的黑箱，而是分成三层文件：

  • L1：原始操作和对话记录；
  • L2：按聊天、题库、知识库等场景整理出的事实；
  • L3：跨场景总结出的个人资料、近期状态和偏好。

你可以查看、修改和追溯这些记忆。例如它可以逐渐记住“你正在学概率论”“你容易混淆条件概率和联合概率”“你偏好先举例再讲公式”。

这比每次重新介绍自己方便，但记忆摘要仍由模型生成，可能总结错。涉及个人信息时，也要把这些文件当作敏感数据保护。

5. 把同一套能力接到其他地方

Partner 可以理解成“有独立人设、资料库和记忆的长期 AI 助手”。它可以在 DeepTutor 网页中使用，也能按配置连接飞书、Telegram、Slack、Discord、钉钉、企业微信等聊天渠道。

My Agents 则可以调用本机的 Claude Code、Codex、Gemini、Kimi、OpenCode 或 MiMo Code CLI，也能导入部分工具的历史对话。

这部分能力很强，但配置较多，更适合技术用户。只是想上传教材问问题的人，可以完全不碰它。

它不是魔法，也不等于老师

项目名称中有 Tutor，但它不能保证真正“懂你”，也没有证据表明它可以稳定替代真人教师。

它的实际效果主要取决于四件事：

  1. 你接入的大模型够不够强；
  2. 上传资料的质量如何；
  3. 文档是否被正确解析和检索；
  4. 你的问题是否具体。

模型太弱时，复杂工具调用可能失败、循环或输出格式错误。资料扫描质量差时，知识库可能根本没读对。检索到了原文，也不代表模型不会理解错。因此更准确的定位是“功能完整的 AI 学习与知识工作台”，而不是“答案永远正确的数字老师”。

项目结构和工作原理

不看代码也可以这样理解它的流程：

浏览器或命令行
       ↓
统一的任务调度器
       ↓
判断当前要聊天、解题、研究、出题还是画图
       ↓
大模型思考并按需调用知识库、搜索、记忆、代码等工具
       ↓
工具结果返回给大模型
       ↓
大模型整理最终答案，并保存会话和必要的记忆

代码层面主要分成这些部分：

目录 作用
deeptutor/ Python 核心，包括 FastAPI 后端、智能体循环、知识库、记忆和工具
web/ Next.js 16 + React 19 前端
deeptutor_cli/ 基于 Typer 的命令行工具
packaging/deeptutor-cli/ 不带网页和服务器依赖的独立 CLI 包
tests/ 后端测试
data/ 运行后生成的配置、聊天、记忆、知识库、日志和密钥等数据

Web、CLI 和 SDK 共用同一个调度器，不是三套互不相干的实现。Chat、Quiz、Research、Visualize、Solve 和 Mastery Path 也大体共用同一套智能体循环，只是目标、提示和可用工具不同。

技术栈

  • 后端：Python 3.11 至 3.13、FastAPI、Uvicorn；
  • 前端：Next.js 16、React 19、TypeScript；
  • 默认知识库：LlamaIndex、本地向量检索、BM25、FAISS；
  • 其他知识库方案：PageIndex、GraphRAG、LightRAG、外部 LightRAG Server、Tencent IMA、Obsidian；
  • 存储：文件、SQLite，部分部署可接 PocketBase；
  • 部署：PyPI、源码、Docker、Docker Compose、Podman、CLI-only；
  • 许可证：Apache License 2.0。

使用前要准备什么

必需项

  • 一台能运行 Docker 的电脑，或者 Python 3.11 至 3.13 加 Node.js 20 以上；
  • 一个可用的大模型；
  • 云模型的 API Key，或已经运行的本地模型服务。

程序可以在没配置模型时启动，但基本不能干活。

知识库额外需要

如果只做普通聊天，不需要 embedding 模型。

如果要使用默认的本地知识库和 RAG，需要再配置一个 embedding 模型。它负责把文本转换成向量，方便从大量资料中找出与问题最相关的段落。可以使用 OpenAI、Gemini、Cohere、Jina、Ollama、DashScope、SiliconFlow 或兼容接口。

更换 embedding 模型或向量维度后，旧知识库通常要重新建立索引，不能把不同模型生成的向量随便混用。

钱花在哪里

DeepTutor 本身开源免费，但不代表使用免费。可能产生费用的地方包括：

  • 大模型 API；
  • embedding API；
  • 网页或论文搜索服务；
  • PageIndex 等托管检索服务；
  • 图像、视频、语音生成；
  • 云端文档解析；
  • IM 平台和远程 MCP 服务。

Research、GraphRAG、Book 和记忆整理通常会发起多轮模型请求，比普通聊天更费 token。使用本地模型可以减少 API 费用，但会消耗自己的内存、显存、硬盘和电力。

最推荐的安装方式：Docker

如果只是想用，不准备改源码，Docker 最省事，也更容易清理和迁移。

第一步：启动

docker run --rm --name deeptutor \
  -p 127.0.0.1:3782:3782 \
  -v deeptutor-data:/app/data \
  ghcr.io/hkuds/deeptutor:latest

然后打开：

http://127.0.0.1:3782

命令中的 127.0.0.1 很重要，它让服务默认只从本机访问。第一次试用时，不要为了方便改成公网暴露。

第二步：配置大模型

进入：

Settings → Models → LLM

填写提供商、Base URL、API Key 和模型名称，然后先做连接测试。可以选择 OpenAI、Anthropic、Gemini、DeepSeek、Qwen、Kimi、OpenRouter、Azure OpenAI 或 OpenAI-compatible 接口等。

如果使用本机 Ollama，Docker 里的 localhost 指的是容器自己，不是你的电脑。Base URL 通常要填写：

http://host.docker.internal:11434/v1

Linux 运行 Docker 时，启动命令可能还需要加入：

--add-host=host.docker.internal:host-gateway

第三步：先测试普通聊天

不要一上来就装 GraphRAG、MCP 和十几个插件。先在 Chat 中问一个简单问题，确认模型输出、中文和流式响应都正常。

例如：

用生活中的例子解释贝叶斯公式，然后出一道简单题让我回答。

第四步：配置 embedding

要上传教材建立默认知识库，再进入：

Settings → Models → Embedding

配置 embedding 提供商并测试连接。本地 Ollama embedding 的地址通常是：

http://host.docker.internal:11434/api/embed

第五步：建立知识库

进入 Knowledge Center：

  1. 新建知识库；
  2. 初次使用选择默认的 LlamaIndex 即可；
  3. 上传 PDF、DOCX、PPTX、XLSX 或文本资料；
  4. 等待解析和索引完成；
  5. 在 Chat 中选择该知识库后提问；
  6. 要求回答附来源，并抽查原文。

遇到扫描版 PDF、公式多或版式复杂的文件时，默认文本解析效果可能不好。项目支持 MinerU、Docling、MarkItDown 和 PyMuPDF4LLM 等解析器，但部分需要额外依赖或服务。先用默认方案，确实读不准再更换。

停止和再次启动

前台运行时按 Ctrl+C 停止。因为示例使用了 --rm，容器会被删除，但 deeptutor-data 数据卷仍然保留配置和资料。再次执行同一条 docker run 命令即可继续使用。

查看数据卷：

docker volume inspect deeptutor-data

不用 Docker：从 PyPI 安装

这种方式适合熟悉 Python 环境的人。

要求：

  • Python 3.11 至 3.13；
  • Node.js 20 以上；
  • 建议单独建立工作目录和虚拟环境。
mkdir -p my-deeptutor
cd my-deeptutor
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -U deeptutor
deeptutor init
deeptutor start

deeptutor init 会询问端口、LLM 和可选 embedding。默认前端端口是 3782，后端端口是 8001。启动后打开终端显示的网址，通常也是 http://127.0.0.1:3782。

Windows PowerShell 激活虚拟环境可使用：

.\.venv\Scripts\Activate.ps1

本地安装默认可能在宿主机的受限子进程中运行模型生成的代码。对安全边界没有把握时，优先使用 Docker，并阅读后面的安全说明。

开发者：从源码启动

准备 Python 3.11 至 3.13 和 Node.js 22 LTS：

git clone https://github.com/HKUDS/DeepTutor.git
cd DeepTutor

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .

cd web
npm ci --legacy-peer-deps
cd ..

deeptutor init
deeptutor start --dev

--dev 会以开发模式启动前端，支持热更新。源码体量已经很大，涉及后端、前端、多种 RAG、工具调用、多用户和容器部署，不适合当作一个下午就能完全看懂的小项目。

命令行用法

不想开网页，可以使用 CLI：

deeptutor chat

单次提问：

deeptutor run chat "用通俗语言解释傅里叶变换"

使用解题能力：

deeptutor run deep_solve "解方程 x^2 - 5x + 6 = 0"

创建知识库：

deeptutor kb create textbook --doc textbook.pdf

指定知识库解题：

deeptutor run deep_solve "根据教材解释这道题" --tool rag --kb textbook

查看配置和记忆：

deeptutor config show
deeptutor memory show

只安装 CLI 的精简包目前要从源码仓库安装：

python -m pip install -e ./packaging/deeptutor-cli
deeptutor init --cli
deeptutor chat

推荐的日常使用流程

如果你的目标是“用自己的教材认真学一门课”，建议这样用：

  1. 先配置一个工具调用能力较好的 LLM；
  2. 配置 embedding；
  3. 按课程或主题建立知识库，不要把所有文件都塞进一个库；
  4. 上传资料后先问几道有明确答案的问题，检查引用是否准确；
  5. 用 Chat 解释概念，用 Solve 讲题；
  6. 每学完一章，用 Quiz 生成练习；
  7. 把错题加入题库，把重要总结放进笔记；
  8. 每隔一段时间检查 Memory，删掉错误总结；
  9. 最后再尝试 Mastery Path、Book、GraphRAG 等复杂功能。

一个比较好的提示词模板：

请只根据我选择的知识库回答。
先用两三句话说结论，再分步骤解释。
每个关键结论注明资料来源和页码；如果资料不足，直接说不知道，不要补写。
最后出两道检查理解的小题，先不要给答案。

数据、隐私和安全

这是使用 DeepTutor 前必须看的一节。

本地部署不等于数据不出电脑

DeepTutor 程序可以在本地运行，但只要你使用云端 LLM、embedding、搜索、文档解析、PageIndex、Tencent IMA、IM 或远程 MCP，相关提示词、附件片段或检索内容就可能发送给第三方。

是否保存、是否用于训练、是否符合学校或公司的合规要求，要看每个服务商自己的条款。不要把涉密资料、学生个人信息或未授权教材直接交给云服务。

data/ 要当作敏感目录

运行数据主要放在 data/，其中可能包括：

  • API Key 和 OAuth 凭据；
  • 聊天记录和附件；
  • 个人学习记忆；
  • 知识库和解析缓存；
  • 日志、账号和权限信息。

配置是普通 JSON/YAML 文件，不能假设默认进行了静态加密。备份、同步和分享整个目录前要检查内容，并限制文件访问权限。

模型生成代码会被执行

Office 技能可以生成 DOCX、PDF、PPTX 和 XLSX。实现方式不是模型直接吐出文件，而是模型写 Python 脚本，再由 DeepTutor 执行。

本地安装和单容器部署中，sandbox_allow_subprocess 默认开启。它虽然有一定限制，但运行模型生成代码始终是实际风险。不需要文件生成功能时，可以在 data/user/settings/system.json 中关闭：

{
  "sandbox_allow_subprocess": false
}

安全要求较高时，使用带独立 sandbox runner sidecar 的 Docker Compose 方案，比在主应用或宿主机里直接运行更稳妥。

不要裸奔到公网

默认认证是关闭的，官方 Docker 示例只绑定 127.0.0.1，适合个人本机使用。如果要让局域网或公网访问，至少需要：

  • 启用认证；
  • 配置精确的 CORS 来源；
  • 使用 HTTPS 和反向代理；
  • 限制注册、工具、MCP 和代码执行权限；
  • 做好 data/ 备份和访问控制；
  • 定期更新版本并查看安全问题。

项目的多用户模式更适合彼此信任的邀请制小团队，不适合互不信任的公开租户。仓库自己的 Compose 注释也说明，runner 对普通用户数据的隔离并非严格的租户级安全边界。

社区插件也有供应链风险

Skills、MCP 服务和 CLI Apps 都能扩展能力，也会扩大权限和攻击面。不要因为页面上能“一键安装”就默认可信。安装前检查来源、脚本、权限和网络访问范围。

上传的文档和抓取的网页还可能包含提示注入内容，诱导模型泄露信息或调用危险工具。对来源不明的材料，应减少可用工具和权限。

优点

功能真正连在一起

知识库、笔记、题库、记忆、写作和聊天可以互相引用，不是很多独立 Demo 的简单拼盘。Web 和 CLI 也共用后端调度逻辑。

知识库选择多

默认 LlamaIndex 已够多数人使用，高级用户还可以选择 PageIndex、GraphRAG、LightRAG、Obsidian 等方案。索引支持版本化重建，重建失败时不必马上破坏旧索引。

记忆相对透明

三层记忆保存为可以检查的文件，并提供追溯关系，比完全隐藏的“模型记住了你”更容易纠错。

安装路径比较完整

项目提供 PyPI、Docker 镜像、源码开发、CLI-only 和多种 Compose 方案。Apache 2.0 许可证也方便研究、修改和二次开发。

工程化不只是演示级

仓库有大量 Python 和前端测试，CI 覆盖 Python 3.11 至 3.13、前端测试、代码格式和导入检查。代码对流式响应、上下文窗口、工具重试、缓存、索引版本和多用户路径等问题都有专门处理。

缺点和现实成本

功能太多，学习成本不低

Chat、Knowledge、Memory、Book、Partner、MCP、Skills、CLI Apps 和多种 RAG 同时存在，新用户很容易不知道从哪开始。最好的办法是先只用 Chat 和默认知识库。

对模型能力有要求

普通问答很多模型都能做，但复杂研究、多轮工具、结构化出题和 Book 生成更依赖强模型。小型本地模型即使接口兼容，也不一定稳定。

高级功能可能很烧钱

GraphRAG 建索引、长报告、Book 和多智能体调用都可能产生大量请求。一定要设置预算和 token 上限，先用小资料测试。

部署矩阵复杂

云模型、本地模型、Docker、反向代理、WebSocket、OAuth、CORS、多用户和代码沙箱组合起来后，排错难度明显增加。

仍是快速变化中的年轻项目

项目首发时间不长，版本更新很快，近期发布记录仍持续修复工具调用、内存、RAG、多用户授权和输出隔离问题。活跃是好事，也意味着升级后可能遇到配置或行为变化。

测试多，不等于所有场景都成熟

自动化测试主要证明代码经过了检查，不证明教学效果、答案正确率、企业级安全或隐私合规。仓库的浏览器端到端测试和完整容器拓扑验证也没有完全覆盖所有组合。

适合谁

  • 想用自己的教材、论文和笔记建立长期 AI 学习空间的人；
  • 愿意配置 API 或本地模型的学生、研究者和教师；
  • 想把 RAG、出题、研究、写作和记忆放在一个系统里的技术用户；
  • 需要私有部署，并愿意自己管理数据和安全的小团队；
  • 想研究智能体、RAG、学习记忆和工具调用架构的开发者。

不适合谁

  • 只想打开网页就用，不想配置模型或处理部署问题的人；
  • 只需要最简单的 PDF 问答，且不需要记忆、题库和写作等功能的人；
  • 希望完全免费，同时又不愿运行本地模型的人；
  • 要求答案绝对正确、可以无人复核自动评分的场景；
  • 医疗、法律、安全工程和正式考试等高风险用途；
  • 需要互联网公开注册、强租户隔离和完整合规审计的平台；
  • 有严格保密资料，却准备接入多个云服务和第三方插件的组织。

最终评价

DeepTutor 的价值不在于“它比所有聊天机器人更聪明”，而在于它把学习过程中常见的材料、提问、练习、笔记、研究、写作和长期记忆串在了一起。对愿意折腾的用户，它可以成为一套很完整的个人 AI 学习基础设施。

但它并不是装完就自动变成名师。模型质量、资料质量、检索效果、费用控制和安全配置都需要使用者负责。普通用户应从 Docker、一个可靠的 LLM 和默认 LlamaIndex 知识库开始，先确认“能稳定根据自己的资料回答”，再逐步开启其他能力。

如果你的需求只是偶尔问一份 PDF，它可能太重；如果你想长期维护自己的课程资料、错题、笔记和学习记忆，它才真正有优势。
